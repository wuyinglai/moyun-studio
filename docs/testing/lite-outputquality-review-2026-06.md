## 6. 主要问题

### 问题 1：LLM 调用超时/失败导致 Fallback（关键问题）

**描述**：第 2 场内容是 `_fallback_section_content` 的硬编码模板，不是真实 LLM 生成。

**证据**：
```
对手借"（最近5章摘要，由系统自动维护）"继续施压，把主角逼到众人面前。
```

这是模板中的占位符，说明 LLM 调用失败。

**影响**：
- 场景 2 完全不可用
- 用户可能不知道内容是 fallback
- 破坏了连续性

**根因分析**：
- LLM 调用超时（90 秒 deadline）
- 网络波动
- 模型响应过慢

### 问题 2：Fallback 内容质量模板化

**描述**：`_fallback_section_content` 生成的内容过于通用，无法体现具体故事上下文。

**问题示例**：
- 使用"（最近5章摘要，由系统自动维护）"占位符
- 无具体人物姓名、冲突细节
- 结尾钩子也是泛化描述

### 问题 3：真实生成存在轻微 AI 腔

**描述**：场次 1、3 存在一些模板化表达，如：
- "那双眸子正缓缓睁开"
- "眼中闪过一丝慌乱"

**影响**：较低，不影响阅读体验，但可通过 Prompt 优化改善。

## 7. Prompt 优化建议

> **注意**：以下建议仅供设计参考，不直接修改 Prompt。需要通过 Phase T3-D 进行正式设计后实施。

### A. 字数约束建议

| 约束项 | 当前状态 | 建议 |
|--------|----------|------|
| 目标字数 | 无明确要求 | 每场 1000-1500 字 |
| 最少字数 | 无 | 每场不少于 900 字 |
| 字数预警 | 无 | 低于 800 字时触发警告 |

### B. 场景结构建议

| 结构项 | 当前状态 | 建议 |
|--------|----------|------|
| 开场 | 无明确要求 | 必须有具体场景/人物/冲突引入 |
| 发展 | 无明确要求 | 必须有 2+ 个冲突升级节点 |
| 高潮 | 无明确要求 | 必须有明确的行动/决定 |
| 结尾钩子 | 有泛化模板 | 必须留下具体悬念，不能泛化 |

### C. 避免 Fallback 建议

| 建议项 | 说明 |
|--------|------|
| 增加 LLM timeout | 当前 90s 可能不够，考虑增加到 120s |
| Fallback 标记 | Fallback 内容应该在 UI 上有明显标记，不让用户误以为是真的生成 |
| Fallback 触发记录 | 记录 fallback 触发原因，便于排查 |
| 重试机制 | Fallback 后自动重试一次 LLM 生成 |

### D. 减少 AI 腔建议

| 问题表达 | 优化建议 |
|----------|----------|
| "那双眸子正缓缓睁开" | 改为更自然的动作描写 |
| "眼中闪过一丝慌乱" | 改为具体的肢体语言或对话 |
| "此人不是别人，正是..." | 改为更自然的引出方式 |

## 8. 产品机制优化建议

### A. Fallback 处理机制

| 建议 | 说明 |
|------|------|
| **Fallback 明确标记** | UI 上显示"内容为自动生成草稿，建议重写" |
| **自动重试** | Fallback 触发后 30 秒内自动重试 LLM |
| **字数不足警告** | 生成后低于 800 字时，显示"字数不足，可以重写" |
| **一键扩写** | 提供"扩写本场"按钮，针对不足场景 |

### B. 质量检查机制

| 建议 | 说明 |
|------|------|
| **生成后评分** | 显示本场质量评分（1-5 星） |
| **字数实时统计** | 编辑器显示实时字数 |
| **冲突推进检查** | 检测是否有明确的冲突/行动/高潮 |
| **续写连贯性检测** | 与前文人物/事件一致性检查 |

### C. 用户干预机制

| 建议 | 说明 |
|------|------|
| **重写按钮** | 对质量不满意可一键重写 |
| **扩写按钮** | 对字数不足的场景一键扩写 |
| **手动续写** | 用户可在任意点手动输入引导后续方向 |
