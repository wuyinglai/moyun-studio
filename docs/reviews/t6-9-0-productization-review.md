## 1. 当前产品能力摘要

**对普通用户而言，墨韵已经可以：**

| 能力 | 说明 | 状态 |
|------|------|------|
| **创建项目** | 支持创建新小说项目，自动生成标准目录结构 | ✅ |

| **触发生成** | Professional 模式支持 Pipeline 多步生成，Lite 模式支持一键续写 | ✅ |
| **生成候选稿** | 高风险操作（rewrite/polish/chat_edit）自动生成 candidate，不直接覆盖正文 | ✅ |
| **预览候选稿** | 右侧面板可查看 candidate 列表和内容预览 | ✅ |

### 核心概念说明

- **场景（Scene）**：`sec-*.md` 文件，约 600-1000 中文字，是写作和生成的最小单位
- **候选稿（Candidate）**：高风险修改的临时版本，审核后才能 adopt 到正式正文
- **Pipeline**：多步生成工作流（如 rewrite 包含 diagnose → draft → depai → logic → rhythm → diff）
- **Dry-run**：模拟生成，不调用真实 LLM，用于测试流程

## 4. 当前阻碍发布的问题清单

### P0：发布前必须修复

| 问题 | 说明 | 影响 |
|------|------|------|
| `.env.example` 变量命名不一致 | `MOYUN_ALLOW_REAL_LLM_SMOKE` vs `ALLOW_REAL_LLM_SMOKE`（代码实际读取后者） | 用户配置时可能混淆 |
| LLM API Key 配置缺少 UI 引导 | 设置页面需要配置 API Key，但缺少引导说明 | 新用户可能不知道如何配置 |
| 错误提示不够友好 | API 错误码直接展示给用户 | 用户无法理解错误原因 |

### P1：建议修复

| 问题 | 说明 | 影响 |
|------|------|------|
| README 入门步骤较长 | 从 clone 到首次生成需要多个命令 | 降低新用户入门体验 |
| candidate/adopt 概念不够直观 | 普通用户可能不理解为什么需要"候选稿" | 降低产品可理解性 |
| dev/test dry-run 按钮易误触 | 虽然只在 dev 模式显示，但位置靠近主流程 | 可能造成测试数据污染 |
| 项目 ID 使用 UUID[:8] | 用户难以识别和区分项目 | 影响用户体验 |
| 缺少本地 LLM（如 Ollama）配置示例 | `.env.example` 只给了 OpenAI 示例 | 想使用本地模型的用户需要自行摸索 |

### P2：可后续优化

| 问题 | 说明 | 影响 |
|------|------|------|
| Pipeline stream 格式非标准 SSE | 当前使用 JSON 消息，不是标准 `event:`/`data:` | 不利于外部工具集成 |
| Task 状态 UI 部分依赖轮询 | 部分场景通过 API 轮询而非 SSE 推送 | 实时性不够 |
| candidate-adopted SSE 未完整验证 | API 层已覆盖，UI 层断言不完整 | 影响事件驱动体验 |
| Batch 未接入 TaskQueue | Batch 独立运行，不发布任务事件 | 状态追踪不统一 |
