# Webnovel Writer vs 墨韵 - 项目对比分析

> 生成时间：2026-05-12  
> 分析目标：深入了解 Webnovel Writer 项目，对比与墨韵项目的异同，找出可借鉴的设计思路

---

## 一、项目定位对比

| 对比维度 | Webnovel Writer | 墨韵 (Moyun) |
|---------|-----------------|---------------|
| **核心定位** | 基于 Claude Code 的长篇网文辅助创作系统 | AI 辅助小说创作平台 |
| **目标用户** | 网文作者（长篇连载） | 中文小说创作者（零门槛） |
| **创作规模** | 支持 200 万字量级 | 支持 5-20 万字规模 |
| **集成方式** | Claude Code 插件（斜杠命令） | 独立 Web 应用（前端+后端） |
| **部署方式** | 本地 Claude Code 环境 | 本地/私有部署（FastAPI + 前端） |

**关键差异**：
- Webnovel Writer 深度绑定 Claude Code，利用 Claude Code 的会话管理能力
- 墨韵是独立应用，提供完整的 Web UI，更适合非技术用户

## 二、技术架构对比

### 2.1 整体架构

| 对比维度 | Webnovel Writer | 墨韵 (Moyun) |
|---------|-----------------|---------------|
| **前端技术** | 无独立前端（依赖 Claude Code 界面 + 只读可视化面板） | HTML/CSS/JavaScript（纯前端，无框架） |
| **后端技术** | Python（RAG 检索模块） | Python + FastAPI（完整后端 API） |
| **AI 集成** | Claude Code 原生集成（继承会话模型） | LiteLLM（支持多模型：GPT-4/Claude/Ollama） |
| **数据存储** | 文件系统（`.story-system/` 目录） | 文件系统（JSON + Markdown） |
| **检索系统** | RAG（嵌入模型 + 重排序模型，fallback 到 BM25） | 无 RAG（直接读取文件上下文） |
| **状态管理** | `.story-system/` 单一事实源 + `.webnovel/` 只读投影 | `meta.json` + `ch-meta.json` 分散式管理 |

### 2.2 核心文件结构对比

#### Webnovel Writer 初始化后的项目结构
```
<小说项目>/
├── .story-system/           # 单一事实源（核心设定、卷纲、章节、审查记录）
│   ├── MASTER_SETTING.json # 全局故事设定
│   ├── volumes/             # 卷纲文件
│   ├── chapters/            # 已写章节文件
│   └── reviews/             # 章节审查记录
├── .webnovel/               # 只读投影层（自动生成，禁止手动修改）
│   ├── state.json           # 项目运行状态
│   ├── index.db             # RAG 检索索引
│   ├── summaries/           # 章节/卷纲摘要
│   └── memory_scratchpad.json # 临时记忆存储
├── references/              # 题材模板库（fallback 参考）
├── agents/                  # 内置 Agent 配置
└── .env                     # RAG 模型 API Key
```

#### 墨韵项目结构
```
workspace/projects/{project_name}/
├── meta.json               # 项目配置
├── context.json            # 上下文统计
├── outline.md              # 大纲文件
├── chapters/               # 章节目录
│   └── vol-{序号}/
│       ├── vol-meta.json   # 卷元数据
│       └── ch-{序号}/
│           ├── ch-meta.json  # 章元数据（含 memory）
│           └── sec-{序号}.md  # 节内容文件
├── characters/              # 角色档案（JSON）
├── materials/extracted/    # 提取结果（情节/场景/摘要）
├── style-guide.md          # 文风指南
├── story-state.md          # 故事全局状态
└── recent-context.md       # 近期上下文摘要
```

**架构设计差异**：
1. **Webnovel Writer**：采用"单一事实源 + 只读投影"的分层设计，所有修改都基于 `.story-system/`，`.webnovel/` 自动生成
2. **墨韵**：采用分散式管理，各文件独立存储，通过 API 统一读写

## 三、核心功能对比

### 3.1 创作流程

| 功能 | Webnovel Writer | 墨韵 (Moyun) |
|------|----------------|---------------|
| **初始化** | `/webnovel-init` 命令（交互式填写） | 新建项目模态框（选择参数 + 三阶段引导） |
| **大纲生成** | `/webnovel-plan <卷号>` | AI 自动生成（阶段 2） |
| **章节生成** | `/webnovel-write <章节号>` | 点击"重写本文件"或"写下一部分" |
| **一致性审查** | `/webnovel-review <章节范围>` | 无内置审查命令（依赖用户手动检查） |
| **记忆管理** | 写前加载 + 写后沉淀 + 专用运维命令 | `ch-meta.json` 存储章节记忆 |
| **可视化面板** | `/webnovel-dashboard`（只读，无需构建） | 完整 Web UI（三栏布局） |

### 3.2 AI 上下文管理

| 对比维度 | Webnovel Writer | 墨韵 (Moyun) |
|---------|----------------|---------------|
| **上下文来源** | `.story-system/` 全量加载 + RAG 检索 | 文件服务读取（按需加载） |
| **遗忘问题** | 持久化存储 + 写前全量加载 | `story-state.md` + `recent-context.md` |
| **幻觉问题** | 合同种子 + 运行时合同 + 事件审计 | 无强制约束机制（依赖 Prompt 设计） |
| **检索增强** | RAG（嵌入模型 + 重排序） | 无（直接读取文件） |
| **记忆机制** | 写前注入 + 写后沉淀 + memory_scratchpad | 章节 memory 字段 |

### 3.3 网文专属功能

| 功能 | Webnovel Writer | 墨韵 (Moyun) |
|------|----------------|---------------|
| **题材模板** | 37 个网文垂直题材模板 | 无（用户自定义参数） |
| **追读力系统** | Hook、爽点、微兑现、债务追踪 | 无 |
| **伏笔管理** | 自动追踪 | `story-state.md` 手动维护 |
| **角色一致性** | 强制规则约束 | 角色档案（JSON） |

## 四、解决的核心问题对比

### 4.1 Webnovel Writer 的核心设计思路

#### 解决「遗忘」问题
1. **持久化单一事实源**：所有核心数据存储在 `.story-system/`，不依赖 AI 临时会话
2. **写前全量上下文加载**：每次写作前自动读取所有相关文件
3. **状态自动同步机制**：章节通过审查后自动触发提交事件，更新状态文件、RAG 索引、摘要、记忆

#### 解决「幻觉」问题
1. **强制规则约束**：合同种子 + 运行时合同 + 事件审计机制
2. **精准上下文检索**：RAG 模块检索高度相关上下文
3. **全流程校验机制**：`preflight` 预检 + `/webnovel-review` 审查
4. **只读投影隔离**：`.webnovel/` 禁止手动修改，避免 AI 篡改核心设定

### 4.2 墨韵的核心设计思路

#### 解决「创作门槛」问题
1. **零门槛创作**：用户只需选择参数，AI 自动生成书名、大纲、章节
2. **三阶段引导流程**：阶段 1（书名）→ 阶段 2（大纲）→ 阶段 3（开始写作）
3. **实时协作**：SSE 实时显示 AI 生成过程，随时干预

#### 解决「质量控制」问题
1. **文风指南**：`style-guide.md` 定义写作风格
2. **故事状态**：`story-state.md` 记录全局状态
3. **近期上下文**：`recent-context.md` 存储最近 5 章摘要
4. **用户反馈**：支持提交反馈和修改日志

**核心差异总结**：
- Webnovel Writer 聚焦**长期连载的一致性**（防遗忘、防幻觉）
- 墨韵聚焦**创作流程的流畅性**（零门槛、实时协作）

## 五、技术实现细节对比

### 5.1 AI 模型集成

| 对比维度 | Webnovel Writer | 墨韵 (Moyun) |
|---------|----------------|---------------|
| **模型支持** | Claude（继承 Claude Code 会话） | 多模型（GPT-4/Claude/Ollama，通过 LiteLLM） |
| **模型配置** | 内置 Agent 默认继承会话模型，支持单独指定 | `.env` 配置 API Key + 模型选择 |
| **流式输出** | Claude Code 原生支持 | SSE 事件流 |
| **重试机制** | Claude Code 内置 | tenacity（指数退避） |

### 5.2 数据存储与检索

#### Webnovel Writer 的 RAG 系统
```
嵌入模型：Qwen/Qwen3-Embedding-8B
重排序模型：jina-reranker-v3
Fallback：BM25 检索
索引文件：.webnovel/index.db
```

#### 墨韵的文件系统
```
存储格式：JSON（元数据）+ Markdown（内容）
读取方式：文件服务（aiofiles）
检索方式：无（直接读取文件）
```

**技术差距**：
- Webnovel Writer 有完整的 RAG 检索系统，能精准召回相关上下文
- 墨韵依赖直接文件读取，上下文精度可能不足

### 5.3 状态管理

| 对比维度 | Webnovel Writer | 墨韵 (Moyun) |
|---------|----------------|---------------|
| **状态存储** | `.story-system/` + `.webnovel/state.json` | `meta.json` + `context.json` |
| **状态更新** | 章节提交事件自动触发 | API 调用时更新 |
| **状态查询** | `/webnovel-dashboard` 可视化面板 | Web UI 实时显示 |

## 六、优缺点分析

### 6.1 Webnovel Writer

**优点**：
1. ✅ **深度集成 Claude Code**：利用 Claude Code 的会话管理能力，无需独立部署
2. ✅ **RAG 检索系统**：精准召回相关上下文，减少幻觉
3. ✅ **强制规则约束**：合同机制防止 AI 篡改核心设定
4. ✅ **网文专属功能**：追读力系统、题材模板、伏笔追踪
5. ✅ **一致性审查**：`/webnovel-review` 命令批量检查剧情连贯性
6. ✅ **持久化存储**：单一事实源设计，跨会话不丢失上下文

**缺点**：
1. ❌ **依赖 Claude Code**：必须使用 Claude Code，无法切换其他 AI 工具
2. ❌ **技术门槛高**：需要配置 RAG 模型 API Key（嵌入模型 + 重排序模型）
3. ❌ **无独立 UI**：依赖 Claude Code 界面，可视化面板功能有限
4. ❌ **Python 依赖**：需要安装 Python 依赖包
5. ❌ **社区依赖**：RAG 模型依赖第三方 API（ModelScope、Jina）

### 6.2 墨韵 (Moyun)

**优点**：
1. ✅ **独立 Web 应用**：完整 UI，用户体验好
2. ✅ **零门槛创作**：三阶段引导流程，适合新手
3. ✅ **多模型支持**：LiteLLM 统一调用，支持 GPT-4/Claude/Ollama
4. ✅ **实时协作**：SSE 实时显示 AI 生成过程
5. ✅ **Prompt 可视化**：右侧面板显示完整 Prompt，透明可控
6. ✅ **自动化等级**：L1 半自动 / L2 连续，灵活控制

**缺点**：
1. ❌ **无 RAG 检索**：上下文精度不足，可能遗漏关键信息
2. ❌ **无强制规则约束**：依赖 Prompt 设计，无法完全防止幻觉
3. ❌ **无一致性审查**：缺少批量检查剧情连贯性的功能
4. ❌ **记忆管理薄弱**：仅依赖 `ch-meta.json` 和 `story-state.md`，未系统化
5. ❌ **无网文专属功能**：缺少追读力系统、题材模板等

## 七、可借鉴的设计思路

### 7.1 从 Webnovel Writer 借鉴

#### 1. 单一事实源设计
**借鉴点**：将所有核心数据存储在一个目录下（如 `.story-system/`），禁止 AI 直接修改，通过提交事件自动更新。

**实施建议**：
- 墨韵当前采用分散式存储（`meta.json`、`ch-meta.json`、各 `*.md` 文件）
- 可以新增 `.story-system/` 目录，作为单一事实源
- 保留现有文件结构，但新增自动同步机制

#### 2. RAG 检索系统
**借鉴点**：使用嵌入模型 + 重排序模型进行精准上下文检索，fallback 到 BM25。

**实施建议**：
- 墨韵当前无 RAG 系统，上下文精度不足
- 可以集成 LiteLLM 的嵌入功能，或调用第三方嵌入 API
- 为每次章节生成前，检索相关上下文（角色、情节、伏笔）

#### 3. 强制规则约束（合同机制）
**借鉴点**：通过"合同种子 + 运行时合同 + 事件审计"机制，强制 AI 遵循故事规则。

**实施建议**：
- 墨韵当前无强制约束，依赖 Prompt 设计
- 可以在 `story-state.md` 中新增"故事规则"字段
- AI 生成章节前，强制加载并遵循这些规则

#### 4. 一致性审查命令
**借鉴点**：`/webnovel-review` 命令批量检查指定章节的剧情连贯性。

**实施建议**：
- 墨韵当前无内置审查功能
- 可以新增 API 端点 `/api/review`，调用 AI 检查章节一致性
- 前端新增"审查"按钮，触发一致性检查

#### 5. 追读力系统
**借鉴点**：内置 Hook、爽点、微兑现、债务追踪等网文专属功能。

**实施建议**：
- 墨韵当前无此类功能
- 可以在 `story-state.md` 中新增"追读力"字段
- AI 生成章节时，自动植入 Hook 和爽点

#### 6. 题材模板库
**借鉴点**：预置 37 个网文垂直题材模板，降低创作启动成本。

**实施建议**：
- 墨韵当前无题材模板，用户需手动选择参数
- 可以在 `workspace/references/` 下新增题材模板库
- 新建项目时，用户可以选择模板，自动填充参数

## 八、改进建议（墨韵项目）

### 8.1 短期改进（1-2 周）

1. **新增一致性审查功能**
   - 后端新增 `/api/review` 端点
   - 前端新增"审查"按钮
   - 调用 AI 检查章节连贯性

2. **强化记忆管理**
   - 将 `ch-meta.json` 的 `memory` 字段标准化
   - 新增"记忆管理"面板，显示所有章节的记忆
   - 支持手动编辑和删除记忆

3. **新增故事规则约束**
   - 在 `story-state.md` 中新增"故事规则"字段
   - AI 生成章节前，强制加载并遵循这些规则
   - 前端新增"故事规则"编辑界面

### 8.2 中期改进（1-2 月）

1. **集成 RAG 检索系统**
   - 使用 LiteLLM 的嵌入功能，或调用第三方 API（如 OpenAI Embeddings）
   - 为每次章节生成前，检索相关上下文
   - 存储索引文件（如 `index.db`）

2. **新增题材模板库**
   - 在 `workspace/references/` 下新增题材模板库
   - 预置常见网文题材（玄幻、都市、科幻等）
   - 新建项目时，用户可以选择模板

3. **新增追读力系统**
   - 在 `story-state.md` 中新增"追读力"字段
   - AI 生成章节时，自动植入 Hook 和爽点
   - 前端新增"追读力分析"面板

### 8.3 长期改进（3-6 月）

1. **单一事实源设计**
   - 重构数据存储方式，采用"单一事实源 + 只读投影"的分层设计
   - 所有修改都基于单一事实源，只读投影自动生成

2. **可视化面板增强**
   - 当前墨韵已有完整 Web UI
   - 可以新增"项目状态"面板，显示实体图谱、章节进度、追读力数据

3. **多模型优化**
   - 当前已支持 LiteLLM
   - 可以为不同任务分配不同模型（如：生成用 Claude，嵌入用 GPT）

## 九、总结

### 9.1 核心差异

| 维度 | Webnovel Writer | 墨韵 (Moyun) |
|------|----------------|---------------|
| **定位** | 技术向（Claude Code 用户） | 产品向（零门槛用户） |
| **核心优势** | 长期连载一致性（防遗忘、防幻觉） | 创作流程流畅性（零门槛、实时协作） |
| **技术复杂度** | 高（RAG + 合同机制） | 中（FastAPI + 文件存储） |
| **用户门槛** | 高（需要配置 RAG API Key） | 低（开箱即用） |

### 9.2 建议

1. **墨韵可以借鉴 Webnovel Writer 的强一致性机制**（RAG、合同、审查）
2. **Webnovel Writer 可以借鉴墨韵的完整 UI 设计**（独立 Web 应用、实时协作）
3. **两者可以融合**：墨韵提供产品化 UI + Webnovel Writer 提供强一致性引擎
