# 墨韵 - 后端架构设计文档

## 一、概述

本文档定义墨韵后端的核心架构，包括目录结构、模块划分、数据模型和API路由。

> **编码规范**：请参考 [编码规范.md](./编码规范.md)

**依赖技术**：
- FastAPI - Web框架
- LiteLLM - LLM统一调用
- aiofiles - 异步文件操作
- python-frontmatter - Markdown元数据
- Jinja2 - Prompt模板渲染
- tiktoken - Token计数
- watchdog - 文件监听
- tenacity - 重试机制

### 3.2 各模块职责（优化后）

| 模块 | 职责 | 深度评估 |
|------|------|---------|
| `api/*` | HTTP请求处理、参数验证、响应格式化 | 浅层 |
| `services/base.py` | 定义抽象接口（FileService, LLMService等） | 接口定义 |
| `core/llm.py` | LLM调用封装、流式输出、重试 | 深层 |
| `core/file_ops.py` | 异步文件读写、目录管理 | 深层 |
| `core/prompt_engine.py` | Jinja2模板加载、变量替换、片段引用（支持依赖注入） | 深层 |
| `core/task_queue.py` | 任务队列管理（仅状态）+ TaskExecutor（执行） | 深层 |
| `core/event_bus.py` | 事件发布/订阅（独立模块，可复用） | 深层 |
| `core/watcher.py` | 文件监听器（仅监听，发布到EventBus） | 深层 |
| `core/snapshot.py` | 版本快照、diff生成 | 浅层 |
| `core/exceptions.py` | 统一异常体系 | 接口定义 |
| `models/*` | 数据结构定义、序列化 | 浅层 |
| `schemas/*` | API请求/响应模型 | 浅层 |

### 3.3 架构优化要点

#### 删除测试（Deletion Test）
- **EventBus**: 删除后，所有模块的事件发布逻辑需要重写 → 深层 ✓
- **TaskExecutor**: 删除后，任务执行逻辑分散到API层 → 深层 ✓
- **PromptEngine**: 删除后，模板渲染逻辑需要重写 → 深层 ✓
- **snapshot.py**: 删除后，快照功能消失但不影响核心 → 浅层

#### 关键深化机会
1. **API层→Core层**：通过Service接口层解耦
2. **PromptEngine→FileService**：依赖注入解耦
3. **TaskQueue职责分离**：状态管理 vs 执行逻辑
4. **FileWatcher→EventBus**：监听 vs 事件分发
5. **异常体系集中**：core/exceptions.py 统一处理

### 6.2 PromptEngine模板加载

```python
class PromptEngine:
    """Prompt模板引擎"""

    def __init__(self, prompts_path: Path, file_service: FileService):
        self.prompts_path = prompts_path  # workspace/prompts/
        self.file_service = file_service
        self.env = Jinja2Environment(
            loader=FileSystemLoader(str(prompts_path))
        )

    def load_template(self, category: str, template_type: str) -> Template:
        """加载模板"""
        template_path = f"{category}/{template_type}/main.md"
        return self.env.get_template(template_path)

    async def render(
        self,
        category: str,
        template_type: str,
        variables: dict[str, Any]
    ) -> str:
        """渲染模板"""
        template = self.load_template(category, template_type)

        # 解析片段引用 @{file_path}
        for key, value in variables.items():
            if isinstance(value, str) and value.startswith("@{"):
                variables[key] = await self._resolve_reference(value)

        return template.render(**variables)

    async def _resolve_reference(self, ref: str) -> str:
        """解析片段引用 @{file_path}"""
        file_path = ref[2:-1]  # 去掉 @{
        content, _ = await self.file_service.read_file(file_path)
        return content
```

```python
    """应用异常基类"""
    def __init__(self, message: str, code: str, details: Any = None):
        self.message = message
        self.code = code
        self.details = details

class ProjectNotFoundError(AppException):
    """项目不存在"""

class FileNotFoundError(AppException):
    """文件不存在"""

class TemplateNotFoundError(AppException):
    """模板不存在"""

class LLMError(AppException):
    """LLM调用错误"""

class InvalidVariableError(AppException):
    """变量无效"""
```

```python
from fastapi import Request

async def app_exception_handler(request: Request, exc: AppException):
    return JSONResponse(
        status_code=400,
        content=error_response(
            message=exc.message,
            code=exc.code,
            details=exc.details
        )
    )

@app.exception_handler(Exception)
async def general_exception_handler(request: Request, exc: Exception):
    return JSONResponse(
        status_code=500,
        content=error_response(
            message="内部错误",
            code="INTERNAL_ERROR",
            details=str(exc) if settings.debug else None
        )
    )
```
