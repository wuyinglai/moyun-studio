# 文件系统设计文档

## 一、总体目录结构

```
workspace/                           ← 工作区根目录
│
├── .moyun/                          ← 运行时状态 ✨NEW
│   └── workflow-runs/              ← 工作流执行状态（JSON，断点续跑用）
│
├── projects/                        ← 所有项目目录
│   └── {project_name}/              ← 项目名称（唯一标识）
│       ├── meta.json                ← 项目配置（名称、类型、模型等）

│       ├── story-state.md           ← 故事全局状态
```

## 二、新增文件说明

### 2.1 文风指南 (style-guide.md)

**位置**：`projects/{project_name}/style-guide.md`

**用途**：定义小说的文风要求，指导 AI 生成符合期望的文字风格

**内容结构**：
```markdown
# 文风指南

## 一、文风定位
- 整体风格：简洁干练/华丽优美/口语化/古风典雅/冷峻硬朗/温暖治愈

## 二、示范文字
- 用户上传的示范文字片段

## 三、写作风格要点
- 句子节奏
- 描写密度
- 语言特点

## 四、写作禁忌
- 避免的表达方式

## 五、题材特点
- 题材特有的表达习惯

## 六、角色说话风格
- 主要角色的说话风格定义

## 七、参考范例
- 用户认可的优秀文风范例
```

**创建时机**：
- 创建项目时自动生成
- 用户可随时编辑

---

### 2.2 故事全局状态 (story-state.md)

**位置**：`projects/{project_name}/story-state.md`

**用途**：记录小说的全局状态，包括主角当前状态、势力变化、伏笔追踪等

**内容结构**：
```markdown
# 故事全局状态

## 一、故事基本信息
- 当前章节、进度、更新时间

## 二、主角状态
- 基础信息
- 能力/境界（根据题材调整）

## 三、主要资源/道具
- 资源列表及当前状态

## 四、势力关系
- 主角所属势力
- 相关势力

## 五、已揭示的重要设定
- 故事中已揭示的设定

## 六、伏笔追踪
- 已埋设但未回收的伏笔
- 已回收的伏笔

## 七、进行中的主线/支线
- 主线进度
- 支线状态

## 八、关键人物关系
- 人物关系最新状态

## 九、待处理事项
- 下一章节需要处理的事项

## 十、章节摘要（最近5章）
- 最近5章的摘要，用于提供近期上下文
```

**更新时机**：
- 每次生成新章节后自动更新
- PipelineRunner._update_after_generation() 自动追加记录

---

### 2.3 近期上下文 (recent-context.md)

**位置**：`projects/{project_name}/recent-context.md`

**用途**：存储最近5章的摘要，用于在生成章节时提供近期情节上下文

**内容结构**：
```markdown
# 近期上下文

## {timestamp} - {file_name}
{content_summary}
...
```

**更新时机**：
- PipelineRunner 在每次生成完成后自动追加条目，保留最近5条

---

### 2.4 用户反馈 (feedback/)

**位置**：`projects/{project_name}/chapters/{vol}/ch-{xxx}/feedback/`

**用途**：记录用户对生成内容的反馈

**文件结构**：
```json
{
  "id": "fb-001",
  "chapter_path": "chapters/vol-01/ch-001/sec-001.md",
  "type": "suggestion",
  "content": "这段对话可以更生动一些",
  "location": "第3段",
  "satisfaction_level": 3,
  "resolved": false,
  "created_at": "2026-05-11T10:00:00",
  "resolved_at": null
}
```

**字段说明**：
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 反馈ID |
| `chapter_path` | string | 关联章节路径 |
| `type` | string | suggestion / error / improvement |
| `content` | string | 反馈内容 |
| `location` | string | 问题位置（可选） |
| `satisfaction_level` | int | 满意度 1-5（可选） |
| `resolved` | bool | 是否已解决 |
| `created_at` | string | 创建时间 ISO8601 |
| `resolved_at` | string | 解决时间（可选） |

**创建时机**：
- 用户提交反馈时创建

---

### 2.5 修改日志 (revision-log/)

**位置**：`projects/{project_name}/chapters/{vol}/ch-{xxx}/revision-log/`

**用途**：记录每次修改的详情

**文件结构**：
```json
{
  "id": "rev-001",
  "chapter_path": "chapters/vol-01/ch-001/sec-001.md",
  "revision_type": "ai_rewrite",
  "description": "管线生成: sec-001.md",
  "word_count_before": 1500,
  "word_count_after": 1800,
  "diff": "@@ -1,5 +1,5 @@...",
  "created_at": "2026-05-11T10:00:00"
}
```

**字段说明**：
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 日志ID |
| `chapter_path` | string | 关联章节路径 |
| `revision_type` | string | ai_rewrite / user_edit / auto_save |
| `description` | string | 修改描述 |
| `word_count_before` | int | 修改前字数 |
| `word_count_after` | int | 修改后字数 |
| `diff` | string | unified diff 文本 |
| `created_at` | string | 创建时间 ISO8601 |

**创建时机**：
- PipelineRunner 在生成完成后自动创建（内容有变化时）
- `_update_after_generation()` 对比 original_content 和 content 生成 diff

## 三、章节元数据 (ch-meta.json)

### 完整结构

```json
{
  "chapter_number": 1,
  "title": "第一章：意外觉醒",
  "section_count": 4,
  "word_count": 0,
  "status": "draft",
  "memory": "",
  "story_state": "",
  "pending_foreshadowing": [],
  "active_quests": [],
  "created_at": "2026-05-11T10:00:00"
}
```

### 字段说明

| 字段 | 类型 | 说明 | 创建时机 |
|------|------|------|---------|
| `chapter_number` | int | 章节序号（全局连续） | 章节创建时 |
| `title` | string | 章节标题 | 章节创建时 |
| `section_count` | int | 本章节数 | 章节创建时 |
| `word_count` | int | 字数统计 | 章节创建时初始0 |
| `status` | string | draft / editing / completed / discarded | 章节创建时 |
| `memory` | string | 章节上下文记忆 | 初始空，AI生成后填充 |
| `story_state` | string | 本章时的故事状态 | 章节创建时 |
| `pending_foreshadowing` | array[string] | 待回收伏笔列表 | 章节创建时 |
| `active_quests` | array[string] | 进行中支线列表 | 章节创建时 |
| `created_at` | string | 创建时间 ISO8601 | 章节创建时 |

**说明**：
- `chapter_number`、`title`、`section_count` 在 wizard 确认大纲时确定
- `pending_foreshadowing` 和 `active_quests` 来自 ch-meta.json（而非 story-state.md）
- 管线生成时通过 `_load_chapter_vars()` 读取这些字段注入模板变量
- **注意**：Python 模型 `ChapterMeta`（`models/chapter.py`）使用不同的字段名（`chapter_index`/`chapter_title`），实际 JSON 序列化以本文档为准

## 五、文件生命周期

### 创建规则

| 文件类型 | 创建时机 | 创建者 |
|----------|----------|--------|
| meta.json | 创建项目时 | 系统 |
| context.json | 创建项目时 | 系统 |
| outline.md | 引导流程时生成 | AI |
| style-guide.md | 创建项目时 | 系统 |
| story-state.md | 创建项目时 | 系统 |
| recent-context.md | 创建项目时 | 系统 |
| vol-meta.json | 创建卷时 | 系统 |
| ch-meta.json | wizard 确认大纲时 | 系统 |
| sec-{序号}.md | wizard 确认大纲时创建空文件 | 系统 |
| feedback/*.json | 用户提交反馈时 | 系统 |
| revision-log/*.json | AI重写/用户修改时 | 系统 |
| 角色档案 | 用户创建/AI提取时 | 用户/AI |
| 提取结果 | AI提取后 | AI |
| 快照文件 | 保存快照时 | 系统 |

### 更新规则

| 文件类型 | 更新时机 | 更新内容 |
|----------|----------|----------|
| meta.json | 用户修改配置时 | 配置字段 |
| context.json | 调用 recalculate-stats 时 | stats |
| outline.md | 用户编辑时 | 大纲内容 |
| style-guide.md | 用户编辑时 | 文风定义 |
| story-state.md | 每次生成章节后 | 追加自动更新记录 |
| recent-context.md | 每次生成章节后 | 追加新条目（保留最近5条） |
| vol-meta.json | 用户重命名卷时 | name |
| ch-meta.json | 用户修改时 | title 等 |
| sec-{序号}.md | AI 生成 / 用户编辑时 | 正文内容 |
| 角色档案 | 用户编辑时 | 档案内容 |
| 提取结果 | 通常不修改 | - |

### 删除规则

**文件不支持物理删除**

| 情况 | 处理方式 |
|------|----------|
| 章节废弃 | 将 status 改为 `discarded`，内容保留 |
| 角色废弃 | 标记为 inactive |
| 提取结果废弃 | 标记为 inactive |
| 快照 | 可清理旧快照，但保留最近 N 个 |

## 六、章节结构规则

### 6.1 层级关系

| 层级 | 命名格式 | 示例 | 说明 |
|------|----------|------|------|
| 卷 | `vol-{序号}` | `vol-01` | 由全文规模决定数量 |
| 章 | `ch-{序号}` | `ch-001` | **全局连续**，不随卷重置 |
| 节 | `sec-{序号}` | `sec-001` | **全局连续**，每章节数由规模动态计算 |

### 6.2 序号规则

- **全局连续**：章、节序号均不重置，从 001 开始递增
- **每章节数**：由作品规模动态计算（总字数 / 1800 ≈ 总节数），通过 wizard 确认大纲时确定

### 6.3 卷元数据 (vol-meta.json)

```json
{
  "volume_number": 1,
  "name": "第一卷：少年出山",
  "chapter_range": [1, 8],
  "total_chapters": 8,
  "created_at": "2026-05-11T10:00:00"
}
```

### 6.4 章节 Memory 机制

每章拥有独立的 `memory`，用于：

| 用途 | 说明 |
|------|------|
| 支持重新生成 | 重新生成某一节时，基于该章 memory 生成 |
| 上下文拼接 | 写新章节时，读取前 3 章的 memory 拼接上下文 |

**更新时机**：
- 章节写完后自动生成/更新 memory
- 用户手动修改章节后更新 memory

## 十、版本管理

### 10.1 文件版本快照

- **保存位置**：`projects/{project_name}/backup/.snapshots/`
- **触发时机**：手动保存或自动保存（前端定时保存触发，见前端实现）
- **命名格式**：`{snapshot_id}.json`
- **后端模块**：`backend/core/snapshot.py`（SnapshotManager）

### 10.2 项目级备份

- **保存位置**：`projects/{project_name}/backup/`
- **触发时机**：手动创建
- **API**: `POST /api/backup` / `POST /api/backup/{backup_id}`（恢复）

## 十二、约束与限制

### 12.1 命名限制

| 对象 | 命名规则 |

## 十三、规则总结

1. **目录即分类**：Prompt 模板按 `generate/extract/transform` 分类，管线模板在 `pipeline/` 下
2. **管线模板结构**：`pipeline/{name}.yaml`（定义）+ `pipeline/{name}/{step_id}.md`（步骤 prompt）
3. **旧模板结构**：`{category}/{type}/main.md`（内容）+ `meta.json`（元数据）
4. **章节结构**：卷 > 章 > 节，章和节序号全局连续
5. **单文件存储**：角色档案和提取结果都是每个对象单独一个文件
6. **角色档案**：`characters/` 目录统一存储角色档案
7. **提取结果**：`materials/extracted/{type}/` 存储提取结果
8. **版本管理**：文件快照 + 项目级备份
9. **信息推断**：ID 类信息从目录/文件名推断，不重复存储
10. **系统变量**：style-guide.md、story-state.md、recent-context.md 等由 PipelineRunner 自动加载
