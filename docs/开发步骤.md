# 墨韵 - AI小说创作助手 开发步骤

## 概述

本文档定义**迭代循环开发模型**，是整个项目的开发纲领。

核心理念：**文档是活着的，不是一次写完就定稿的**。每深入思考一步，相关文档都要同步更新，确保所有文档始终一致。

---

## 一、迭代循环模型（核心纲领）

### 1.1 核心理念

开发不是线性阶段，而是**每个模块都走一遍完整的迭代循环**：

```
┌───────────────────────────────────────────────┐
│                                               │
│   ┌─────────┐   ┌─────────┐   ┌─────────┐  │
│   │ 1.思考   │──>│ 2.文档   │──>│ 3.同步   │  │
│   │ 深化     │   │ 更新     │   │ 检查     │  │
│   └─────────┘   └─────────┘   └─────────┘  │
│                             │                │
│                             v                │
│   ┌─────────┐   ┌─────────┐   ┌─────────┐  │
│   │ 6.下一   │<──│ 5.验收   │<──│ 4.代码   │  │
│   │ 模块     │   │ 钩子     │   │ 实现     │  │
│   └─────────┘   └─────────┘   └─────────┘  │
│                                               │
└───────────────────────────────────────────────┘
```

### 1.2 六个迭代步骤

#### 步骤1：思考深化
- 深入理解当前模块的需求
- 发现之前文档的不足或错误
- 形成新的认知

#### 步骤2：文档更新
- 根据新认知，更新相关文档
- 可能是《原型生成说明》，也可能是《功能清单》或《文件系统设计》
- **每次只更新一个文档**（避免混乱）

#### 步骤3：同步检查（强制）
- 根据"文档同步检查机制"，检查依赖当前文档的其他文档
- 如果需要更新，先完成同步，再继续
- **未完成同步检查，不得进入步骤4**

#### 步骤4：代码实现
- 根据更新后的文档，实现代码
- 遵循《功能清单》里的执行逻辑
- Prompt必须独立存储，不得硬编码

#### 步骤5：验收钩子（强制）
- 对照《功能清单》逐项打勾
- 使用搜索工具确认每项功能都有对应代码
- **验收不通过，不得进入步骤6**

#### 步骤6：进入下一模块
- 当前模块验收通过后，才能进入下一模块
- 如果下一模块的发现需要修改前面文档，回到步骤1

### 1.3 核心原则

1. **文档优先** - 所有代码实现前，先确认文档完备
2. **契约驱动** - 功能清单、API契约 = 开发契约，契约不确认不动手
3. **Prompt独立** - Prompt必须独立存储，禁止硬编码在代码里
4. **验收钩子** - 每个模块开发完成后，必须对照《功能清单》逐项打勾
5. **文档同步** - 每次更新一个文档，必须检查所有依赖它的文档
6. **追问到底** - "还有吗？"是口头禅

## 二、开发前准备工作

> **重要提示**：在正式开发代码之前，必须先完成以下所有准备工作。

### 2.1 环境检查清单

| 检查项 | 说明 | 验证方法 |
|--------|------|----------|
| Python版本 | ≥ 3.10 | `python --version` |
| 包管理器 | pip | `pip --version` |
| Git | 用于版本控制 | `git --version` |
| 编辑器 | VS Code / PyCharm | - |
| 浏览器 | Chrome/Firefox（开发测试用） | - |

### 2.2 依赖安装

```bash
# 1. 克隆项目（如已有可跳过）
git clone <repository-url>
cd newmoyun

# 2. 创建Python虚拟环境
python -m venv venv

# 3. 激活虚拟环境
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

# 4. 安装后端依赖
pip install -r requirements.txt

# 5. 安装Playwright（如需E2E测试）
pip install playwright
playwright install chromium

# 6. 复制环境变量文件
cp .env.example .env
# 编辑 .env，填入实际配置
```

### 2.3 初始化项目

```bash
# 1. 运行项目初始化脚本
python setup_project.py

# 2. 验证目录结构
# 应该看到以下目录：
# - backend/
# - frontend/
# - workspace/
# - workspace/prompts/generate/
# - workspace/prompts/extract/
# - workspace/prompts/transform/
# - workspace/prompts/templates/

# 3. 验证Prompt模板数量
ls workspace/prompts/generate/  # 应有10个目录
ls workspace/prompts/extract/  # 应有4个目录
ls workspace/prompts/transform/ # 应有4个目录
ls workspace/prompts/templates/ # 应有7个文件
```

### 2.4 LLM配置

在 `.env` 文件中配置LLM：

```env
LLM_PROVIDER=openai
LLM_API_KEY=your-api-key-here
LLM_MODEL=gpt-4
LLM_API_BASE=https://api.openai.com/v1
```

**VS Code 扩展**：
- Python
- Pylance

**settings.json 示例**：

  "editor.formatOnSave": true,

    "**/__pycache__": true,

### 2.6 准备工作验证

完成以上步骤后，运行以下验证：

```bash

python -c "import fastapi, litellm, aiofiles, tiktoken; print('依赖正常')"

# 2. 验证Jinja2模板
python -c "from jinja2 import Environment, FileSystemLoader; print('Jinja2正常')"

# 3. 验证前端CDN资源可用性
# 在浏览器中打开 prototype.html，确认无报错
```

### 2.7 常见问题

| 问题 | 解决方案 |
|------|----------|
| pip安装失败 | 使用 `pip install --upgrade pip` |
| 虚拟环境激活失败 | 使用 `python -m venv --clear venv` 重新创建 |
| LLM连接失败 | 检查 `.env` 配置，或使用 Ollama 本地部署 |
| Playwright安装失败 | 使用管理员权限运行，或换用 `playwright install --with-deps` |

## 七、验收钩子工作流

每个模块开发完成后，按以下流程验收：

```
1. 打开《功能清单》，定位到对应模块编号
2. 逐项检查执行逻辑是否有对应代码实现
3. 检查API契约中是否有对应的API端点
4. 确认技术选型与依赖文档中是否有对应的技术栈
5. 逐项打勾，更新验收状态
6. 追问："还有吗？这个模块的功能都实现了吗？"
```

**禁止行为**：
- ❌ 模块未验收就进入下一模块
- ❌ 跳过功能清单中的任何子项
- ❌ 验收时只说"应该没问题"
