# 去 AI 化与叙事质量规则提炼

> **创建时间**：2026-06-05
> **阶段**：桥接任务 - Lite Prompt 与专业版 Prompt 准备
> **状态**：规则整理完成，暂不接入生产 Prompt
> **注意**：去 AI 化只是 Python + LLM 写作质量与一致性引擎的一部分，专业版应重点建设该引擎体系（详见 `python-llm-writing-quality-engine-2026-06.md`）

## 1. 背景

当前 T3-D6 主要围绕 Lite Prompt 的**字数、行动链、冲突推进、结尾钩子**做实验，旨在：
- 减少 too_short 问题
- 增强结构稳定性
- 降低 template_leak 问题

但后续还需要更系统的**去 AI 化和叙事质量规则**，这对：
- Lite Prompt 真实实验后的优化（T3-D6.5+）
- 专业版 Prompt 设计（Phase T4）
- 长期输出质量提升

都有重要意义。

本文档从《大明：极乐教主》项目的执行规范中提炼通用写作质量规则，为后续工作做准备。

## 2. 核心判断

### 2.1 去 AI 化不等于删词

去 AI 化不应简单理解为：
- ❌ 删掉特定词表
- ❌ 强制替换句式
- ❌ 过度追求口语化

而应分为两个层次：

| 层次 | 说明 |
|------|------|
| **语言层** | 减少 AI 腔、解释腔、模板腔 |
| **叙事层** | 增强目标、冲突、状态变化、潜台词、人物动作 |

### 2.2 语言层规则

目标：
- 减少 "这是因为、因此、所以" 等解释因果句式
- 减少 "她知道、他意识到、他感到" 等读心句式
- 减少 "尽管、然而" 等过度转折连接
- 减少模板化比喻（如 "像一场风暴" 等陈词滥调）
- 减少空泛情绪词（如 "非常悲伤、极其愤怒"）

### 2.3 叙事层规则

目标：
- 每场有明确场景目标
- 每场有具体阻碍
- 每场有状态变化（处境、关系、认知至少一个改变）
- 对话有潜台词
- 人物有专属动作（不是通用动作）
- 场景物件参与叙事

## 3. Lite Prompt 可用轻量规则

Lite Prompt 需要简洁，避免约束过重。建议先接入 **3-5 条轻量规则**：

### 3.1 心理活动规则

**规则 1：不直接读心，用动作和对话呈现**

```text
❌ 不要：她感到一阵愤怒，她知道自己被骗了。
✅ 应该：她猛地攥紧拳头，指节发白："你骗我？"
```

**Lite 接入建议**：在现有 Variant C 的结尾钩子规则之前，加入这条规则，避免过度复杂。

### 3.2 解释因果规则

**规则 2：少用解释因果的连接词**

```text
❌ 不要：因此，她决定离开。这是因为他欺骗了她。
✅ 应该：她转身就走。
```

**Lite 接入建议**：加入去解释因果规则，但不要做成强制删词表，而是引导写法。

### 3.3 推进变化规则

**规则 3：每次续写至少推进一个具体变化**

```text
❌ 不要：他们聊了聊，又继续赶路。
✅ 应该：他们聊了聊，她发现地图是假的。
```

**Lite 接入建议**：这与现有 Variant C 的冲突推进规则可以结合。

### 3.4 情绪呈现规则

**规则 4：用动作和细节呈现情绪，少用空泛情绪词**

```text
❌ 不要：她非常悲伤，泪流满面。
✅ 应该：她盯着那张纸，指尖在抖，眼泪砸在纸面上，晕开一小片湿痕。
```

**Lite 接入建议**：轻量版本可以只要求"至少有一个动作细节呈现情绪"。

### 3.5 结尾钩子规则

**规则 5：结尾保留未解决问题或动作钩子**

```text
❌ 不要：事情就这样结束了。
✅ 应该：她推开门，看见他站在那里，手里拿着刀。
```

**Lite 接入建议**：这与现有 Variant C 的结尾钩子规则一致，可复用。

## 4. 专业版 Prompt 可用完整规则

专业版 Prompt 可以更完整，包含叙事质量各维度：

### 4.1 场景目标与阻碍

| 维度 | 说明 |
|------|------|
| **场景目标** | 本场人物具体想做什么 |
| **阻碍** | 阻碍是什么（人、事、物） |
| **失败代价** | 不做/做不到的后果 |

### 4.2 状态变化

要求每场至少让一项发生变化：

| 变化类型 | 说明 |
|----------|------|
| **处境变化** | 主角处境更危险/安全 |
| **关系变化** | 人物关系变好/变坏 |
| **认知变化** | 主角发现新信息/改变想法 |
| **资源变化** | 得到/失去某件关键物品 |

### 4.3 对话与潜台词

```text
✅ 要有潜台词：不要只说字面意思
✅ 对话要推动冲突：不是闲聊
✅ 对话要符合人物：不是通用模板
```

### 4.4 人物专属动作

```text
❌ 不要：他生气地说
✅ 应该：他重重拍了一下桌子，茶碗跳了起来
```

### 4.5 场景物件参与叙事

```text
❌ 不要：场景背景只是摆设
✅ 应该：场景里的东西（刀、信、地图）参与冲突推进
```

### 4.6 长短句节奏

```text
- 紧张场景用短句
- 抒情场景可适度长句
- 避免全篇同一节奏
```

### 4.7 写后自检

生成完成后可检测：
- too_short（字数）
- template_leak（模板词）
- explain_phrases（解释因果）
- mind_reading（读心）
- emotion_telling（空泛情绪）
- weak_scene_flags（弱场景标记：状态无变化）

## 5. 不建议直接接入的规则

### 5.1 过细的成人题材词表

- ❌ 不把特定题材的敏感词表直接写进通用 Prompt
- ❌ 不对所有题材使用相同的内容限制
- ✅ 应按题材分类配置（未来可扩展）

### 5.2 过强的零容忍规则

- ❌ Lite 不适合零容忍检测（会导致 fallback 过多）
- ✅ 专业版可选强约束模式
- ✅ 检测脚本可以提示但不强制重写

### 5.3 密度阈值规则

- ❌ 不把密度阈值（如"每3句必须有一个动作"）全部塞进生成 Prompt
- ✅ 密度阈值更适合检测脚本使用（写后检测）
- ✅ 生成 Prompt 可轻量提示，但不做硬性规定

## 6. 后续接入建议

### 6.1 Lite 接入建议

**阶段 1（T3-D6.4）：只接入 3 条**

1. 不直接读心，用动作和对话呈现
2. 少用解释因果的连接词
3. 每次续写至少推进一个具体变化

**阶段 2（T3-D6.5+）：可选再接入**

- 情绪呈现规则
- 结尾钩子规则（已有）

### 6.2 专业版接入建议

**阶段 1（Phase T4）：完整叙事质量检查**

- 场景目标与阻碍
- 状态变化检测
- 对话潜台词提示
- 专属动作建议
- 场景物件参与提示

**阶段 2（T4.1+）：可选项开关**

- 用户可选择轻量/中等/强约束
- 用户可选择哪些维度启用

### 6.3 检测脚本可扩展方向

现有 `quality_flags` 可扩展：

| 新增 Flag | 说明 | 适用阶段 |
|-----------|------|----------|
| explain_phrases | 检测解释因果句式 | 专业版 |
| mind_reading | 检测读心句式 | 专业版 |
| emotion_telling | 检测空泛情绪词 | 两版都可 |
| weak_scene_flags | 检测状态无变化场景 | 专业版 |
