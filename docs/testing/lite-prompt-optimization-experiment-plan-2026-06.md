# Lite Prompt 优化实验方案

> **创建时间**：2026-06-05
> **阶段**：Phase T3-D6
> **状态**：方案设计完成，未接入生产

---

## 1. 背景

Phase T3-D5 已完成 Lite 生成低质量检测与质量标记，系统现在可以识别：

- `too_short`：正文长度低于 800 字
- `template_leak`：正文中出现模板占位词或系统提示词
- `quality_flags`：低质量标记列表
- `quality_warning`：面向用户的质量警告
- `quality_score`：1-5 的规则评分

这意味着我们已经具备了 Prompt 优化的基础评估能力。

本阶段不直接修改生产 Prompt，而是先建立实验方案和样例变体，避免一次性修改主 Prompt 导致风格、成本、稳定性不可控。

---

## 2. 当前问题

根据 T3-B / T3-C / T3-D 的测试结果，当前 Lite 生成链路的主要质量问题包括：

1. 单场字数不稳定
2. 个别场景可能低于 800 字
3. 有时缺少明确行动链
4. 有时冲突推进不足
5. 结尾钩子不稳定
6. 可能出现模板占位词
7. 某些段落偏总结式、说明式
8. 连续生成时需要更强的"承接上一场、推进下一场"约束

其中，fallback/template 问题已经通过 fallback_used、retry、candidate 化和 template_leak 检测进行了安全兜底；Prompt 优化主要解决"正常 LLM 生成时质量不稳定"的问题。

---

## 3. 现有 Prompt 链路

Lite 写正文主流程大致包括：

1. 前端触发写下一场景
2. 后端读取当前项目、故事状态、风格指南、近期上下文
3. 后端通过 `prompt_engine.render("generate/continuation", {...})` 组织 Prompt
4. LLM 生成正文
5. 后端进行 retry / fallback / quality 检测
6. 正常正文写入目标 sec 文件
7. 前端更新编辑器和 FlowPanel

**现有 Prompt 位置**：`prompts/generate/continuation/main.md`

**现有 Prompt 特点**：
- 目标字数：约 800 中文字，允许范围 600-1000 中文字
- 有结尾留承接点要求
- 有去AI味要求（通过 include depai-rules.md）
- 没有明确的行动链约束
- 没有明确的冲突推进约束
- 没有明确禁止模板占位词

本阶段不直接修改生产 Prompt，只设计 Prompt 约束变体。

---

## 4. 实验目标

Prompt 优化实验的目标是：

1. 单场正文稳定在 1000-1500 字
2. 最低不低于 900 字
3. 每场至少包含 3 个行动段落
4. 每场必须有明确冲突推进
5. 每场结尾必须留下下一场钩子
6. 禁止输出模板占位词
7. 减少总结式、说明式、AI 腔
8. 保持文本适合继续连续生成
9. 不显著增加生成失败率
10. 不显著增加 fallback 触发率

---

## 5. 实验组设计

本实验设置 5 个组：

| 组别 | 名称 | 说明 |
|------|------|------|
| Baseline | 当前 Prompt | 不增加任何新约束 |
| Variant A | 字数约束 | 增加目标字数和最低字数 |
| Variant B | 字数 + 行动链 | 在 A 基础上增加三段行动链 |
| Variant C | 字数 + 行动链 + 冲突推进 + 结尾钩子 | 推荐优先测试 |
| Variant D | 完整约束 + 禁止模板词 + 降低 AI 腔 | 最强约束组 |

推荐优先测试 Variant C，因为它在质量提升和 Prompt 复杂度之间较平衡。

---

## 6. 评分指标

每个实验组连续生成 3 场，记录：

### 自动指标

1. 每场字数
2. `quality_flags`
3. `quality_score`
4. `too_short` 是否出现
5. `template_leak` 是否出现
6. fallback_used 是否出现
7. retry_used / retry_count
8. write_skipped 是否出现

### 人工评分

每场按 1-5 分评分：

1. 连贯性
2. 可读性
3. 画面感
4. 冲突推进
5. 人物行动明确性
6. 与前文一致性
7. 节奏控制
8. 废话程度
9. AI 腔程度
10. 是否适合继续写

---

## 7. 实验流程

1. 选择同一个测试项目和同一个开局
2. Baseline 生成连续 3 场
3. Variant A 生成连续 3 场
4. Variant B 生成连续 3 场
5. Variant C 生成连续 3 场
6. Variant D 生成连续 3 场
7. 记录每组：
   - 三场字数
   - 平均字数
   - too_short 次数
   - template_leak 次数
   - fallback 次数
   - retry 次数
   - 人工评分
8. 汇总比较
9. 选择最优约束
10. 再决定是否进入生产 Prompt 小范围接入

---

## 8. Prompt 约束方向

### A. 字数约束

目标：

- 每场 1000-1500 字
- 最低 900 字
- 不要少于 6 个自然段

风险：

- 字数约束过强可能导致废话增多
- 模型可能为了凑字数降低节奏

### B. 三段行动链

要求每场至少包含：

1. 角色主动行动
2. 外部阻力或冲突升级
3. 角色做出选择或付出代价

风险：

- 所有场景结构过于相似
- 需要避免机械化

### C. 冲突推进

要求每场必须让以下至少一项发生变化：

1. 主角处境更危险
2. 目标更明确
3. 敌对方行动升级
4. 关键资源变化
5. 人物关系变化
6. 新信息出现

风险：

- 过度推进会导致节奏太快

### D. 结尾钩子

每场结尾应留下：

1. 未解决的问题
2. 新威胁
3. 新选择
4. 新地点
5. 新人物行动

风险：

- 钩子过多可能显得套路化

### E. 禁止模板词

禁止输出：

- "最近5章摘要"
- "系统自动维护"
- "占位"
- "TODO"
- `{{ ... }}`
- "以下是"
- "本章主要讲述"
- "总结来说"

风险：

- 禁止词太多可能误伤正常表达

## 9. 推荐实验顺序

建议按以下顺序推进：

1. Phase T3-D6.1：新增实验 Prompt 文件，不接生产
2. Phase T3-D6.2：新增实验脚本，运行 Baseline / Variant A-D
3. Phase T3-D6.3：形成对比报告
4. Phase T3-D6.4：选择最优约束
5. Phase T3-D6.5：小范围接入生产 Prompt
6. Phase T3-D6.6：回归连续生成测试

---

## 10. 推荐优先测试 Variant C

优先测试 Variant C，原因：

1. 比 Variant A 更能改善结构
2. 比 Variant B 更强调冲突推进
3. 比 Variant D 更少硬性限制
4. 不会过早引入过多禁止词
5. 更适合先做小范围实验

Variant C 的核心是：

- 1000-1500 字
- 最低 900 字
- 至少 3 个行动段落
- 明确冲突推进
- 结尾留下下一场钩子

---

## 11. 风险

1. Prompt 过长导致模型成本增加
2. 字数约束导致废话增多
3. 行动链约束导致结构机械
4. 冲突推进约束导致节奏过快
5. 禁止词可能误伤正常文本
6. 不同题材适配效果不同
7. 生产 Prompt 改动可能影响现有测试结果

---

## 12. 验收标准

T3-D6 阶段只验收实验方案，不验收生产效果。

T3-D6 通过标准：

1. 有完整实验方案
2. 有 Baseline / Variant A-D
3. 有评分指标
4. 有实验流程
5. 有风险说明
6. 未修改生产 Prompt
7. 未修改业务代码
8. 前端 build 通过
9. 文档格式正常

---

## 13. 结论

Prompt 优化应以实验方式推进，不应直接修改生产 Prompt。

当前推荐路线：

1. 先写实验方案
2. 再新增实验 Prompt
3. 再跑 variants
4. 再选择最优约束
5. 最后小范围接入生产 Prompt

T3-D6 完成后，建议进入 T3-D6.1：新增实验 Prompt 文件，不接生产。
