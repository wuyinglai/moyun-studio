# Moyun Studio v0.2.0-alpha Release Notes

## Release Type

Alpha / pre-release candidate for the Professional writing flow.

## Release Date

2026-06-13

## Highlights

- Professional scene writing flow validated with real LLM smoke coverage.
- Candidate preview / adopt / delete lifecycle verified for safe revision.
- Existing-scene generation stays candidate-first instead of silently overwriting formal text.
- `write_next_scene` action is mapped as `continue` / `续写`.
- Continuity and generation warnings are visible and persisted during the active generation flow.
- User-facing LLM and generation error messages are easier to understand.
- FILE_CONFLICT and candidate safety remain part of the release gate.

## What Changed

### Professional Writing Flow

- Scene-level writing remains the core unit: `sec-*.md` represents one scene.
- New or empty target scenes may be written directly.
- Existing scene content is protected by candidate generation or confirmation paths.
- Candidate preview does not modify formal scene text.
- Candidate adopt remains the explicit step that can update the source scene.

### Real LLM and Warning Visibility

- Real LLM smoke validation covered the Professional write-next-scene path.
- Long-context and quality warnings are surfaced through SSE warning flows.
- Warning visibility was hardened so warnings are not missed before generation completion.
- Continuity anchors were refined to reduce noisy matches.

- T7.4 RC1 final validation report completed.
- Release checklist and known issues are now prepared for v0.2.0-alpha.

## Known Issues

- Small-context models may still need stricter token truncation.
- Long-context generation can still weaken or omit individual character details.
- Continuity anchor extraction may still produce low-frequency noise.
- Slow real LLM responses still need a more complete cancel and retry experience.
- Local model or custom API endpoint misconfiguration can still cause generation failures.
- This alpha release is not recommended for important production drafts without backups.

See [KNOWN_ISSUES.md](../../KNOWN_ISSUES.md) for the full alpha known-issues list.

## Upgrade / Run Notes

- No database migration is required.
- Keep `.env` local and do not commit API keys.
- Configure a valid LLM provider before real generation.
- Use test projects for important experiments during alpha validation.
- Start backend and frontend as described in [README.md](../../README.md).

## Safety Notes

- High-risk rewrite / polish / chat edit operations should remain candidate-first.
- Do not adopt candidates without reviewing the preview.
- Keep backups of valuable writing projects before long real LLM sessions.
- Real LLM smoke depends on an available endpoint and API key, but secrets must not be committed.
