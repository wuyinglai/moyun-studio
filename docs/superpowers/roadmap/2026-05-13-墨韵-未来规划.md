## 一、设计哲学

### 核心原则

1. **简单至上** — 用户不需要理解底层架构，点一下就有效果。越简单越好，不搞复杂编排界面
2. **即时反馈** — 写作是立即可视化的，所有操作都应几秒内出结果，不需要像视频渲染一样等待
3. **渐近式复杂度** — 新手只用 5 个按钮，进阶用户可以写自定义 Prompt，底层三层抽象（Prompt → Skill → Agent）用户不感知
4. **最小有效功能** — 宁可少做一个功能，也不做一个用户用不明白的功能。每个功能必须有清晰的场景

### 保留墨韵底色，吸收 WW 精华

| 保留 | 吸收 |
|------|------|
| 独立 Web 应用，三栏 UI | 合同机制（防幻觉核心） |
| 零门槛创作体验 | 后端多轮生成管线（多步迭代，单次输出） |
| 实时流式反馈 | 结构化审查 + 证据引用 |
| 多模型支持（LiteLLM） | 创意约束包（反套路/差异化） |
| Prompt 管理中台 | 轻量级 RAG 检索 |

### 三层架构（用户不感知）

```
用户感知层:   工具栏按钮 + 右侧 Prompt 编辑区 + 自定义快捷工具
                    ↓ 由
能力抽象层:  Agent (自主写作) → Skill (多步编排) → Prompt (原子指令)
                    ↓ 存储
持久化层:    Prompt 文件 + 合同文件 + 审查指标 + RAG 索引
```

## 三、近期规划 — Prompt 体系重构（优先级最高）

> **目标：** 把墨韵从"一个 Prompt 用到底"升级为"多 Prompt 可切换、可自定义、即改即用"
> **工期预估：** 1-2 周

### 3.1 系统预置工具按钮

将现有 11 个按钮精简为 5 个固定按钮，不可编辑，覆盖核心写作需求：

| 按钮 | 作用 | 操作范围 | 输出方式 |
|------|------|---------|---------|
| **改写** | 语言优化、结构调整 | 当前文件全文 | 覆盖当前文件 |
| **扩写** | 丰富细节、充实内容 | 当前文件全文 | 覆盖/追加当前文件 |
| **缩写** | 精简浓缩 | 当前文件全文 | 覆盖当前文件 |
| **生成** | 创建新文件 | 基于项目上下文 | 创建新文件（已有则提示覆盖） |
| **对比** | 原文 vs 改写后对比 | 当前文件 | 侧边栏显示差异 |

**说明：** 原有的批量生成、质量审查、提取、反馈、修改日志、Token 等功能，属于不常用或少用功能，放到菜单栏或设置中，不占主工具栏位置。

### 3.2 系统预置提炼类 Prompt

系统全权管理，用户不感知，不展示在界面中。后台自动运行：

- 角色一致性检查
- 设定偏移检测
- 时间线冲突检查
- 关键信息提取（供上下文注入使用）

提炼结果输出到一个固定的分析文件（如 `_analysis.md`），用户可在侧边栏查看，但不需关心 Prompt 本身。

### 3.3 用户自定义 Prompt

#### 存储方式
- **路径：** `.moyun/custom-prompts/{prompt-name}.md`
- **作用域：** 全局（所有项目可用）
- **格式：** 标准的 Markdown 文件，支持引用其他文件
- **数量：** 多个，不设上限

#### 分类

自定义 Prompt 分为两类，创建时选择：

| 类型 | 用途 | 输出 |
|------|------|------|
| **生成式 Prompt** | 基于多个输入文件生成新内容 | 新文件或覆盖当前文件 |
| **提炼式 Prompt**（本期暂不开放自定义） | 从文章中提取结构化信息 | 系统使用，用户不感知 |

#### 编辑方式
- **快速编辑：** 直接在右侧面板的 Prompt 文本域中修改
- **深度编辑：** 点击后在主编辑区打开，享受完整的 MD 编辑体验
- **保存即更新：** 改完保存，下次应用即为新版本

#### 引用机制

在 Prompt 内容中可使用以下方式引用其他文件：

**方式一：文件引用（拖拽支持）**
```
请参考以下素材： [角色设定.md] [世界观.md] [第3章.md]
```
- 支持从文件树拖拽文件到 Prompt 编辑区，自动生成 `[文件名.md]` 链接
- 系统应用 Prompt 时自动解析引用，将对应文件内容注入

**方式二：系统变量**
```
当前文件：{{current_file}}
项目大纲：{{outline}}
角色设定：{{character_sheet}}
世界观：{{world_building}}
```
- 系统变量由系统自动填充，用户直接写在 Prompt 中即可
- 初期预置上述 4-5 个最常用变量，后续可按需扩展

#### 创建入口

```
入口一：右侧面板 → [+] 添加自定义 → 输入名称 → 创建
入口二：从已有 Prompt「另存为」自定义版本
```

#### 多来源

用户自定义 Prompt 主要来自：
1. 从零创建
2. 修改现有 Prompt 后另存
3. 导入他人分享的文件

**不需要**从聊天记录保存——聊天栏是即时指令，用完即完。

### 3.4 右侧面板改造

```
┌────────────────────────────┐
│ [提示词]                    │
│ ┌──────────────────────┐   │
│ │ 选择 Prompt: [▼]      │   │  ← 切换系统/自定义 Prompt
│ └──────────────────────┘   │
│                             │
│ ┌─ Prompt 编辑区 ─────────┐ │
│ │                         │ │
│ │ 当前 Prompt 内容...      │ │  ← 直接编辑，改完即用
│ │ 可以使用 [文件引用.md]    │ │  ← 支持拖拽文件生成引用
│ │ 和 {{系统变量}}          │ │
│ └─────────────────────────┘ │
│ [💡 应用此 Prompt]          │  ← 紧跟在编辑框下方
│                             │
│ ─── 快捷工具 ──────────── │
│ [✏️ 改写] [📖 扩写] [📦缩写] │  ← 系统预置，一点即用
│ [🌟 模仿金庸] [🌟 检查时间线]│  ← 用户自定义工具

```

**交互说明：**
1. 顶部 Prompt 选择器切换不同 Prompt
2. 中间编辑区直接修改 Prompt 文本
3. 「应用此 Prompt」将当前 Prompt 作用于当前文件
4. 快捷工具区一键执行对应 Prompt，不弹确认框
5. 自定义工具自动从 `.moyun/custom-prompts/` 同步

### 3.5 应用 Prompt 的流程

```
用户在右栏选中 Prompt → 点「应用」（或点快捷工具按钮）
  → 前端调用 POST /api/apply-prompt
  → 后端：
    1. 解析 Prompt 中的 [文件引用.md] → 读取对应文件内容
    2. 解析 {{系统变量}} → 从项目上下文填充
    3. 组装完整 Prompt
    4. 调用 AI 流式生成
    5. 将流式增量写入目标文件（覆盖或新建）
  → 前端 SSE 实时显示生成过程
  → 完成后提示用户
```

### 3.7 后端多轮生成管线

> **放在近期的原因：** 当前单轮 Prompt 生成质量不够，多轮迭代是提升质量的最高性价比方案，且前端完全无感知。

**问题：** 当前"单 Prompt → 一次 AI 调用 → 输出"的模式，生成质量取决于 Prompt 写得有多好，缺少中间的自检和修正环节。

**方案：** 后端将所有修改/生成操作改造为多轮管线，但前端仍然是"点一下等结果"。

#### 管线流程

```
用户点「改写」
  → 后端接收请求
  → 第一轮：按用户选择的 Prompt 生成初稿
  → 第二轮（自检）：检查初稿是否有逻辑断裂、设定偏移、角色不一致
  → 第三轮（修正）：修复自检发现的问题
  → 第四轮（润色）：语言润色 + 风格适配
  → 流式返回最终结果给前端
```

#### 核心设计原则

1. **前端零感知** — 用户看到的是一个持续的流式输出，不需要知道背后有几轮
2. **每轮可独立开关** — 通过配置控制每轮的启用/禁用，方便调试
3. **失败容忍** — 任何一轮失败时，fallback 到上一轮结果，不影响用户体验

#### 后端改动

- 修改 `backend/api/generate.py`，将单次 LLM 调用改为多轮管线
- 管线步骤可配置：`pipeline_steps: [draft, self_review, fix, polish]`
- 每步独立 Prompt，可分别调整
- 远期可在此基础上升级为独立的 Agent 模块

### 3.8 与聊天栏的关系

| | Prompt 体系 | 聊天栏 |
|--|-----------|--------|
| **定位** | 可复用的工具 | 即时指令 |
| **使用场景** | 频繁使用的写作辅助 | 临时、一次性需求 |
| **内容来源** | 系统预置 / 用户编写 | 用户当前输入 |
| **是否保存** | 永久保存 | 用完即完 |
| **复用方式** | 点一下执行 | 每次都要打字 |

## 四、中期规划

> **目标：** 引入合同机制、创意约束、审查系统，全面提升写作质量
> **工期预估：** 5-8 周

### 4.1 故事规则（轻量合同机制）—— 防幻觉核心

**来源：** 墨韵 × WW 理念融合改造计划 · 第一阶段

**问题：** 当前无强制规则约束，AI 可能偏离核心设定。
**方案：** 引入故事规则文件，写作前自动注入 Prompt，不需要专门的编辑 UI。

#### 文件结构

项目根目录下一个 `story-rules.md` 文件，跟普通文件一样编辑：

```
workspace/projects/{name}/
└── story-rules.md                # 故事规则（替代 WW 的 contract.json）
```

#### story-rules.md 格式

```markdown
# 故事规则

## 硬约束（必须遵守）
- 主角不能突然获得未铺垫的能力
- XX角色已死不能复活
- 不能使用现代语言描写古代场景

## 伏笔跟踪
- 伏笔A：第2章埋下 → 需在第5章前回收
- 伏笔B：第3章埋下 → 需在第8章前回收

## 当前章节指引
- 目标：揭示反派身份
- 时间锚点：紧接第三章结尾
- 距离决战还剩：3 章
- 章末悬念：主角是否信任了新盟友？

## 避免的写法
- 「突然明白了」
- 「心中一震」
- 「不禁感叹」
```

#### 与普通文件同等待遇

- `story-rules.md` 出现在文件树中，用户可随时打开编辑
- 支持语法高亮和常规编辑操作
- **不需要**单独的编辑面板或 Tab

#### 后端
- 在后端多轮生成管线中，自动将 `story-rules.md` 内容注入 Prompt
- 不需要单独的合同验证服务——规则作为 Prompt 的一部分约束 AI

> **与 WW 方案的区别：** WW 用 JSON + 三层合同 + 强制验证（违反则阻断生成）。墨韵用 Markdown 文件 + Prompt 注入（规则是约束而不是阻断）。更轻量，用户更容易理解，但约束力稍弱。以后可以逐步加强验证。

### 4.2 充分性闸门（Hard Gate）—— 防跳步

**来源：** 墨韵 × WW 理念融合改造计划 · 第一阶段

**问题：** 用户在未完成前置准备时直接开始写作，可能导致后续质量问题。
**方案：** 在关键流程节点设置闸门检查。

闸门节点：

```
阶段1（书名创意）闸门：
  ✅ 书名已确认
  ✅ 一句话故事已填写

阶段2（大纲生成）闸门：
  ✅ 卷纲已生成且确认
  ✅ 章节结构已计算
  ✅ 创意约束包已生成（见 4.3）

阶段3（开始写作）闸门：
  ✅ contract.json 已初始化
  ✅ 至少一个角色档案已创建
```

### 4.3 创意约束包 —— 反套路 + 差异化

**来源：** 墨韵 × WW 理念融合改造计划 · 第二阶段

**问题：** 相同题材的作品容易同质化，缺少差异化。
**方案：** 新建项目时，在阶段 2（大纲生成前）生成 2-3 套创意约束包供用户选择。

每套包含：
- 一句话卖点
- 反套路规则 1 条
- 硬约束 2-3 条
- 主角缺陷驱动
- 反派镜像
- 开篇钩子

用户选择后写入 `contract.json` 的 `rules` 字段。

### 4.4 一致性审查 + 结构化报告

**来源：** WW 对比 + 墨韵 × WW 理念融合改造计划 · 第四阶段

**问题：** 缺少批量检查剧情连贯性的功能。
**方案：** 新增审查 Agent，输出结构化审查报告。

#### 审查流程

```
用户选中章节 → 点击「审查」
  → review_agent 分析：
    1. 读取章节内容 + contract.json + story-state.md
    2. 检查：连续性、角色一致性、设定偏移、伏笔
    3. 输出结构化 JSON
  → 前端展示审查报告
  → 用户选择「自动修复」或「稍后处理」
```

#### 审查报告格式

```json
{
  "chapter": 42,
  "overall_score": 0.85,
  "issues": [
    {
      "type": "continuity",
      "severity": "blocking",
      "description": "主角在上一章受伤，本章未提及伤势",
      "evidence": "第41章末尾：'肋骨断裂三根'；第42章：主角正常奔跑",
      "suggestion": "在章节开头加入伤势描写"
    }
  ],
  "blocking_count": 1,
  "passed": false
}
```

#### 审查指标落库

审查结果写入 `review_metrics.json`：
- 各维度评分（连续性、角色一致性、设定合规等）
- 触发的 anti-patterns 清单
- 对未来写作的建议

`contract.json` 的 `anti_patterns` 字段会根据审查结果自动更新。

### 4.5 强化记忆管理

**来源：** WW 对比

**问题：** 当前记忆管理薄弱，仅依赖 `ch-meta.json` 的 memory 字段。
**方案：**
- 标准化所有章节的记忆结构
- 写前自动加载前 N 章摘要和关键状态
- 写后自动沉淀关键信息
- 支持用户手动编辑和查看记忆

## 五、远期规划

> **工期预估：** 3-6 个月

### 5.1 RAG 检索系统

**来源：** WW 对比 + 墨韵 × WW 理念融合改造计划 · 第三阶段

**轻量方案（推荐起步）：**
- 使用 `rank_bm25` 做关键词检索（已验证可用）
- 对已写章节建立 BM25 索引
- 写作前检索 top-5 相关段落注入 Prompt

**进阶方案（可选）：**
- 使用 LiteLLM 的嵌入接口
- 用户配置嵌入模型 API Key（可选）
- 无配置时 fallback 到 BM25

### 5.2 Skill 编排

**来源：** Prompt 讨论延伸

在 Prompt 层之上提供流程编排能力：
- 将多个 Prompt 串联成一个工作流
- 如：先分析文风 → 再润色 → 再对比
- 界面保持简单——不对用户暴露"编排"概念，而是提供"组合工具"按钮
- 编排结果等同于一个更强大的自定义工具

### 5.3 Agent 层（自主创作）

**来源：** Prompt 讨论延伸

实现创作 Agent，能自主规划章节结构、选择合适的 Prompt/Skill：
- 用户设定目标（如"写第 5 章，3000 字"）
- Agent 规划步骤 → 选择工具 → 执行 → 反思 → 迭代
- **用户不直接操作 Agent**——Agent 只是后台让 AI 更智能的引擎
- 最终交付结果给用户确认

### 5.4 网文专属功能

**来源：** WW 对比

- **追读力分析：** Hook 密度、爽点频率、节奏评估
- **伏笔自动追踪：** 记录伏笔的埋设和回收状态
- **人物关系图谱：** 可视化角色之间的关联
- **题材模板库：** 37 个网文垂直题材模板

### 5.5 单一事实源重构

**来源：** WW 对比

长期考虑将数据存储重构为"单一事实源 + 只读投影"模式：
- 所有修改基于单一源目录
- 只读投影自动生成
- 防止 AI 篡改核心设定

### 优先级排序逻辑

| 排序 | 项目 | 理由 |
|------|------|------|
| **P0** | Prompt 体系 | 用户感知最强、改造量适中、独立可验证（1-2 周） |
| **P0** | 后端多轮生成管线 | 单轮质量不够，多轮迭代性价比最高，前端零感知（与 Prompt 体系并行） |
| **P1** | 故事规则 + 充分性闸门 | 防幻觉核心，轻量方案改造量小（1-2 周） |
| **P1** | 一致性审查 | 直接影响输出质量，与故事规则互补（1-2 周） |
| **P2** | 创意约束包 | 提升作品差异化（1 周） |
| **P2** | 强化记忆管理 | 系统性提升跨章一致性（1 周） |
| **P4** | RAG + Skill 编排 + Agent + 网文功能 | 远期基础设施，不急于推进 |

## 七、附录

### 附录 A：Prompt 分类参考

```
Prompt 体系
├── 系统预置（用户不可编辑）
│   ├── 修改类：改写、扩写、缩写  → 工具栏按钮
│   ├── 生成类：生成              → 工具栏按钮
│   ├── 对比类：对比              → 工具栏按钮
│   └── 提炼类：角色一致性、设定偏移、时间线检查  → 后台自动运行
│
└── 用户自定义（可编辑，全局存储）
    ├── 生成式 Prompt  → 可引用多文件，创建新内容
    └── 提炼式 Prompt  → 本期暂不开放自定义
```

### 附录 C：与聊天栏的关系界定

| 维度 | Prompt 体系 | 聊天栏 |
|------|-----------|--------|
| 定位 | 可复用的写作工具 | 即时写作指令 |
| 使用场景 | 频繁使用的辅助功能 | 临时/一次性需求 |
| 指令生命周期 | 永久保存 | 用完即失 |
| 创建方式 | 用户直接编写或修改 | 用户自然语言输入 |
| 交互模式 | 点按执行 | 对话式交互 |
| 适合用户 | 所有用户（新手直接点按钮，高手写 Prompt） | 所有用户 |
