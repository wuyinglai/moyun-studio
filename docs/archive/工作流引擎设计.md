# 墨韵 - 工作流引擎设计

> 在 Pipeline（单管线）之上提供多步骤编排能力：顺序执行、循环嵌套、文件操作、变量传递。用户可自定义工作流 YAML 并通过前端编辑器管理。

**版本：1.0 | 更新日期：2026-05-14**

> 2026-05-20 对齐说明：本文记录旧版工作流引擎的 YAML 与执行机制。后续专业版会在此基础上统一为 `Workflow -> Chain -> Node` 模型，并将 Prompt、人工确认、文件读写、记忆更新、质量审稿都视为节点。新版方向见 [产品架构-人机协同工作流.md](产品架构-人机协同工作流.md) 和 [专业版节点化改造计划.md](专业版节点化改造计划.md)。

## 一、概述

工作流引擎（WorkflowRunner）是 Pipeline 的上层编排层。它不直接调用 LLM，而是将 Pipeline 作为步骤类型之一，通过 YAML 定义步骤序列，支持：

| 特性 | 说明 |
|------|------|
| 顺序执行 | 按定义顺序逐个执行步骤 |
| Loop 循环 | 嵌套循环，自动注入循环变量 |
| Pipeline 步骤 | 调用已有管线（generate/rewrite/extract 等） |
| 文件操作 | 创建目录、复制/删除文件 |
| 变量解析 | `{{ variables.xxx }}`、`{{ steps.step_id.output }}`、`{{ var\|pad:N }}` |
| 断点续跑 | 每步执行后自动保存状态，支持恢复 |
| SSE 进度 | 实时推送 step_start/step_done/loop_iteration 事件 |
| 自定义编辑器 | 前端可视化编辑，三步搞定 |

### 1.1 与 Pipeline 的关系

```
┌─────────────────────────────────────────┐
│            WorkflowRunnder              │ ← 编排层（工作流）
│  ┌──────────┐  ┌──────────┐  ┌───────┐  │
│  │ Pipeline │  │ Loop     │  │ File  │  │
│  │ （步骤）  │  │ （循环）  │  │（操作）│  │
│  └──────────┘  └──────────┘  └───────┘  │
└─────────────────────────────────────────┘
          │ 调用
┌─────────────────────────────────────────┐
│            PipelineRunner               │ ← 执行层（管线）
│  多步 LLM 调用、模板渲染、@{path} 引用   │
└─────────────────────────────────────────┘
```

## 二、工作流 YAML 定义

### 2.1 文件位置

`workspace/workflows/{name}.yaml`

### 2.2 格式

```yaml
name: write-chapters          # 标识名（文件名）
label: 批量写章节              # 显示名称
description: 对已有项目批量生成多章正文

# 全局变量（用户可覆盖）
variables:
  volume_number: "1"
  chapter_start: "1"
  chapter_count: "10"

steps:
  - id: loop_chapters
    label: 逐章写作
    type: loop                # pipeline | loop | file
    count: "{{variables.chapter_count}}"
    var: ch
    steps:
      - id: calc_chapter_number
        label: 计算章节号
        type: pipeline
        pipeline: generate
        output: "projects/{{project_id}}/chapters/vol-{{variables.volume_number|pad:2}}/ch-{{ch|pad:3}}/sec-001.md"
        output_mode: append
```

### 2.3 字段说明

#### 步骤通用字段

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 步骤唯一标识 |
| `label` | string | 是 | 显示名称 |
| `type` | string | 是 | `pipeline` / `loop` / `file` |

#### pipeline 类型

| 字段 | 类型 | 说明 |
|------|------|------|
| `pipeline` | string | 管线名称（如 `generate/blueprint`） |
| `input` | string | 输入文件路径（可选，读取为 `file_content`） |
| `output` | string | 输出文件路径（支持模板变量） |
| `output_mode` | string | `overwrite` / `append` / `dimension_file` |
| `extra_vars` | dict | 额外模板变量 |

#### loop 类型

| 字段 | 类型 | 说明 |
|------|------|------|
| `count` | string | 循环次数（数字或 `{{ variables.xxx }}`） |
| `var` | string | 循环变量名（如 `vol`、`ch`），在子步骤模板中通过 `{{ var }}` 访问 |
| `steps` | array | 子步骤列表（递归结构） |

#### file 类型

| 字段 | 类型 | 说明 |
|------|------|------|
| `action` | string | `mkdir` / `copy` / `delete` |
| `path` | string | 目标路径 |
| `input` | string | 源路径（copy 时必填） |
| `output` | string | 目标路径（copy 时必填） |

### 2.4 完整示例：full-novel.yaml

```yaml
name: full-novel
label: 完整小说创作
description: 从蓝图到大纲再到逐卷逐章写作的全自动创作流程

variables:
  volume_count: "3"
  chapters_per_volume: "20"

steps:
  - id: blueprint
    label: 生成小说蓝图
    type: pipeline
    pipeline: generate/blueprint
    output: "projects/{{project_id}}/blueprint.md"

  - id: outline
    label: 生成大纲
    type: pipeline
    pipeline: generate/outline
    input: "{{steps.blueprint.output}}"
    output: "projects/{{project_id}}/outline.md"

  - id: worldbuilding
    label: 生成世界观设定
    type: pipeline
    pipeline: generate/worldbuilding
    output: "projects/{{project_id}}/materials/worldbuilding.md"

  - id: characters
    label: 生成主要角色
    type: pipeline
    pipeline: generate/character
    output: "projects/{{project_id}}/characters/main.md"

  - id: write_volumes
    label: 逐卷写作
    type: loop
    count: "{{variables.volume_count}}"
    var: vol
    steps:
      - id: create_volume_dir
        label: 创建卷目录
        type: file
        action: mkdir
        path: "projects/{{project_id}}/chapters/vol-{{vol|pad:2}}"

      - id: write_chapters
        label: 逐章写作
        type: loop
        count: "{{variables.chapters_per_volume}}"
        var: ch
        steps:
          - id: generate_chapter
            label: "生成第{{vol}}卷第{{ch}}章"
            type: pipeline
            pipeline: generate
            output: "projects/{{project_id}}/chapters/vol-{{vol|pad:2}}/ch-{{ch|pad:3}}/sec-001.md"
            output_mode: append

          - id: extract_settings
            label: 提取设定
            type: pipeline
            pipeline: extract
            output: "projects/{{project_id}}/chapters/vol-{{vol|pad:2}}/ch-{{ch|pad:3}}/sec-001.md"
            output_mode: dimension_file
```

## 三、变量解析

### 3.1 支持的语法

| 模式 | 示例 | 说明 |
|------|------|------|
| `{{ project_id }}` | `{{project_id}}` | 替换为当前项目 ID |
| `{{ variables.xxx }}` | `{{variables.volume_count}}` | 全局变量 |
| `{{ variables.xxx\|pad:N }}` | `{{variables.volume_number\|pad:2}}` | 数字补零（N 位） |
| `{{ steps.step_id.output }}` | `{{steps.blueprint.output}}` | 引用前序步骤输出路径 |
| `{{ loop_var }}` | `{{ch}}` | 循环变量（由 loop 的 var 字段定义） |
| `{{ loop_var\|pad:N }}` | `{{vol\|pad:2}}` → `01` | 循环变量补零 |

### 3.2 解析顺序

1. `{{project_id}}` — 文本替换
2. `{{variables.xxx}}` — 遍历 context.variables 替换
3. `{{steps.step_id.output}}` — 遍历 context.step_outputs 替换
4. 正则解析 `{{variables.xxx\|pad:N}}` / `{{steps.xxx.output}}`（含过滤器）
5. 正则解析 `{{var\|pad:N}}` / `{{var}}`（循环变量）

### 3.3 resolve_int

`count` 字段使用 `resolve_int()` 解析，支持 `"{{variables.chapter_count}}"` 或 `"15"` 两种写法。

## 四、后端架构

### 4.1 核心文件

| 文件 | 职责 |
|------|------|
| `backend/core/workflow.py` | WorkflowContext + WorkflowRunner（步骤调度、状态持久化） |
| `backend/api/workflows.py` | 5 个 API 端点 |
| `backend/schemas/workflow.py` | Pydantic 模型 |
| `workspace/workflows/*.yaml` | 工作流定义文件 |

### 4.2 WorkflowContext

```python
class WorkflowContext:
    project_id: str
    variables: dict[str, str]          # 用户变量
    loop_vars: dict[str, str | int]    # 循环变量
    step_outputs: dict[str, str]       # step_id → 输出文件路径

    def resolve(text: str | None) -> str        # 解析模板变量
    def resolve_int(text: str | None) -> int    # 解析后转整数
    def set_loop_var(name: str, value) -> None  # 设置循环变量
```

### 4.3 WorkflowRunner

```python
class WorkflowRunner:
    def __init__(self, workflows_path, prompts_path, llm_service, file_service, state_dir=None)

    # 加载
    def load_workflow(name) -> WorkflowDef
    def list_workflows() -> list[WorkflowDef]
    def save_workflow(req: WorkflowSaveRequest) -> WorkflowDef
    def delete_workflow(name) -> None

    # 执行
    async def run(workflow_name, project_id, variables, stop_event, run_id) -> AsyncGenerator[dict, None]

    # 状态
    _save_state(run_id, ...)     # step_done 时自动保存
    _load_state(run_id) -> dict  # 恢复时使用
    _delete_state(run_id)        # 执行完毕清理
```

### 4.4 SSE 事件流

执行工作流时以 `event: xxx` `data: {...}` 格式推送：

| 事件 | 时机 | 关键字段 |
|------|------|---------|
| `workflow_start` | 开始 | run_id, workflow, label, total_steps, restored, completed_paths |
| `step_start` | 步骤开始 | step_id, label, type, path |
| `loop_iteration` | 循环迭代 | step_id, label, path, var, value, current, total |
| `step_done` | 步骤完成 | step_id, label, type, path, status, output |
| `step_skip` | 断点续跑跳过 | step_id, label, type, path, status="skipped", output |
| `workflow_done` | 全部完成 | run_id, message |
| `workflow_error` | 执行失败 | run_id, message |
| `workflow_stopped` | 用户停止 | message |

Pipeline 步骤的事件（task_start, thinking, prompt, generation, done 等）通过 step_id 注入转发。

### 4.5 状态持久化

保存在 `.moyun/workflow-runs/{run_id}.json`：

```json
{
  "run_id": "wf-a1b2c3d4",
  "workflow": "write-chapters",
  "project_id": "my-novel",
  "status": "running",
  "variables": { "chapter_count": "5" },
  "loop_vars": { "ch": 3 },
  "step_outputs": { "calc_chapter_number": "projects/.../sec-001.md" },
  "completed_paths": ["wf-xxx.loop_chapters.1.calc_chapter_number"],
  "updated_at": "2026-05-14T10:00:00"
}
```

断点续跑：
1. `POST /api/workflows/run` 时可传入 `run_id` 恢复
2. 引擎加载 saved_state，恢复 variables/loop_vars/step_outputs
3. 路径在 `completed_paths` 中的步骤自动跳过
4. Loop 路径含迭代序号（如 `wf-xxx.loop.3.calc`），精确到单次迭代

## 五、API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/workflows` | 列出所有工作流 |
| GET | `/api/workflows/{name}` | 获取工作流详情（含步骤树） |
| POST | `/api/workflows/save` | 保存（创建或更新） |
| DELETE | `/api/workflows/{name}` | 删除工作流 |
| POST | `/api/workflows/run` | 运行工作流（SSE 流式） |
| POST | `/api/workflows/stop/{run_id}` | 停止运行 |
| GET | `/api/workflows/runs/{run_id}` | 查询运行状态 |

### 5.1 保存请求体

```json
{
  "name": "write-chapters",
  "label": "批量写章节",
  "description": "批量生成多章正文",
  "variables": { "volume_number": "1", "chapter_count": "10" },
  "steps": [
    {
      "id": "loop_chapters",
      "label": "逐章写作",
      "type": "loop",
      "count": "{{variables.chapter_count}}",
      "var": "ch",
      "steps": [
        {
          "id": "calc",
          "label": "计算章节号",
          "type": "pipeline",
          "pipeline": "generate",
          "output": "projects/{{project_id}}/.../ch-{{ch|pad:3}}/sec-001.md",
          "output_mode": "append"
        }
      ]
    }
  ]
}
```

### 5.2 运行请求体

```json
{
  "workflow": "write-chapters",
  "project_id": "my-novel",
  "variables": { "chapter_count": "5" }
}
```

variables 为可选覆盖，不传则使用 YAML 中的默认值。

## 六、前端组件

### 6.1 组件文件

| 文件 | 职责 |
|------|------|
| `frontend/src/composables/useWorkflow.ts` | 工作流 composable（列表/详情/运行/保存/删除） |
| `frontend/src/components/right-panel/WorkflowPanel.vue` | 三模式面板：列表 → 详情 → 编辑器 |
| `frontend/src/components/right-panel/StepEditor.vue` | 递归步骤编辑器（支持 Pipeline/Loop/File 三种类型） |
| `frontend/src/components/right-panel/RightPanel.vue` | 注册「📋 工作流」标签页 |

### 6.2 三种模式

**列表模式** — 展示所有工作流卡片，每张卡片显示：
- 名称 + 步骤数
- 描述
- 默认变量值
- 编辑/删除按钮

**详情模式** — 点击工作流进入：
- 步骤预览（带类型图标）
- 变量覆盖输入
- 运行/停止按钮
- 实时执行日志

**编辑器模式** — 新建或编辑：
- 基本信息（标识名、名称、描述）
- 变量管理（添加/删除键值对）
- 步骤管理（三种类型切换、参数配置、↑↓ 排序、删除）
- Loop 子步骤可递归嵌套编辑
- 保存按钮

### 6.3 类型切换规则

步骤类型变更时自动重置无关字段：

| 原类型 → 新类型 | 保留 | 清空 |
|----------------|------|------|
| → pipeline | pipeline, output, output_mode, input | action, path, count, var, steps |
| → loop | count, var, steps | pipeline, action, path |
| → file | action, path, input, output | pipeline, count, var, steps |
