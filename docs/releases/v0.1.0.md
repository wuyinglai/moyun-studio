# Moyun Studio v0.1.0 Release Notes

## Release Type

Open-source preview — local-first AI fiction writing studio.

## Highlights

- **Local-first AI fiction writing studio**: All data stays on your machine. No cloud database, no account required.
- **Scene-level writing model**: `sec-*.md` means a single scene (~600-1000 Chinese characters), not a traditional chapter. Scenes are the smallest unit for writing and generation.
- **Candidate-based safe revision flow**: High-risk operations (polish, rewrite, chat edit) generate candidate drafts instead of overwriting the main text. Adopt only after review.
- **Lite and Professional entry points**: Quick-start Lite mode for focused writing, full Professional workbench for project management.
- **Demo Novel example project**: A complete near-future suspense demo at `examples/demo-novel/`.
- **Release check script**: One-command pre-release validation at `scripts/release-check.ps1`.

## Safety and Reliability Improvements

### Package A — Pipeline overwrite/rewrite protection

Legacy `output_mode=overwrite` and `rewrite` modes can no longer directly write existing scene files. The pipeline normalizes these to safe modes (`write_scene`, `candidate`, `append`). The `overwrite` value remains only as `LEGACY_COMPAT` in schema/policy/docs for backward compatibility.

### Package B — Lite path safety

`backend/api/lite.py` now validates `project_id`, `current_file`, `target_file`, and `output_file` against path traversal. `../`, `..\\`, absolute paths, Windows drive paths, and forbidden segments (`.git`, `node_modules`, `__pycache__`, `.env`, `.config.json`) are rejected.

### Package C — FileService routing for core project files

- `story-state.md` — routed through FileService (C1)
- `style-guide.md` and `meta.json` — routed through FileService (C2)
- `recent-context.md` and `.chapters-meta.json` — routed through FileService (C3)
- Workflow memory updates for `story-state.md` and `recent-context.md` — routed through FileService (C4)

All core project memory files now use safe project-relative paths. Raw `Path.read_text()` / `Path.write_text()` has been removed from these API modules.

### Package D — Materials API security

Material file reads/writes now go through FileService. Direct `Path.unlink()` deletion has been replaced with `FileService.delete_file()`, which safely moves files to trash via `TrashService`. Path traversal in `material_type` and `item_id` is validated and rejected.

### Package E — API Key leakage prevention

- `llm.py` `test_connection` error handler now redacts `sk-*` patterns and `api_key=*` patterns from log output.
- Frontend `ErrorBoundary.vue` and `main.ts` already redact sensitive patterns from console output.
- `llm.ts` already strips `apiKey` from localStorage serialization/deserialization.
- Playwright test artifacts (`playwright-report/`, `test-results/`) are gitignored.
- No real API keys are tracked in the repository.

## Example Project

A complete demo novel is available at `examples/demo-novel/`:

- **Genre**: 近未来悬疑 (Near-future suspense)
- **Title**: 黑塔信号 (Black Tower Signal)
- **Standard path**: `chapters/vol-01/ch-001/sec-001.md`
- **Key concept**: `sec-*.md` always means a single scene, not a chapter or section

To use it, copy into your workspace:

```powershell
Copy-Item -Recurse examples/demo-novel workspace/projects/demo-novel
```

## How to Run Release Check

```powershell
powershell -ExecutionPolicy Bypass -File scripts/release-check.ps1
```

The script runs:
1. `git diff --check` — whitespace errors
2. Solo guardrails — safety rule violations
3. Backend safety tests (A-E) — 313 tests
4. Full backend tests
5. Frontend lint & build (if `node_modules` exists)
6. Mock E2E (if available)

**Real LLM E2E is not run by default.** It requires setting `MOYUN_E2E_REAL_LLM=true` and should never use committed API keys.

## Known Limitations

- **No conflict detection on memory/material endpoints**: `story_state`, `style_guide`, `recent_context`, `workflows`, and `materials` endpoints do not yet expose `expected_mtime` / `expected_hash` parameters. FileService supports it internally, but the API layer does not validate concurrent edits. This is safe for single-user local-first usage but should be addressed before multi-window workflows become common.
- **Some non-core API files still use raw I/O**: `llm.py`, `lite.py`, `prompts.py`, `feedback.py`, `tokens.py`, `wizard.py`, `projects.py`, `revision_log.py`, `backup.py`, and `config.py` still use `Path.read_text()` / `Path.write_text()`. These handle workspace-level config, prompt templates, and initialization — not core project memory files. They need future classification and routing.
- **Real LLM E2E is optional**: Not part of the default release check. Requires explicit environment variable and a real API key.
- **Workspace `.config.json` is local-first config storage**: It stores LLM provider settings including API keys. This is intentional for a local-first application. The file must remain gitignored.
