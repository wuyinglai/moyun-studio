# ADR-0001: 架构优化 - 服务解耦与职责分离

## 状态
已通过

## 日期
2026-05-11

## 背景
根据 Matt Pocock 的 `improve-codebase-architecture` 技能分析，墨韵后端存在以下架构问题：
1. API层直接依赖Core层具体实现
2. PromptEngine与FileService紧耦合
3. TaskQueue职责过重（状态管理+任务执行）
4. FileWatcher多职责混合
5. 异常体系分散

## 决策

### 1. 统一异常体系
创建 `core/exceptions.py`，定义完整的异常层次：
- `MoyunException` 基类
- `ProjectError` / `FileError` / `TemplateError` / `LLMError` / `TaskError` 分类异常
- 所有异常包含 `code`, `message`, `details` 属性
- 提供 `to_dict()` 方法便于API响应

### 2. Service接口层
创建 `services/base.py`，定义抽象接口：
- `FileServiceInterface`
- `LLMServiceInterface`
- `PromptEngineInterface`
- `TaskQueueInterface`
- `EventBusInterface`
- `SnapshotServiceInterface`

API层只依赖接口，不依赖具体实现。

### 3. PromptEngine依赖注入
- `PromptEngine.__init__()` 接收可选的 `file_service` 参数
- 提供 `set_file_service()` 方法用于运行时注入
- 测试时可注入 Mock 实现

### 4. TaskQueue与TaskExecutor分离
- **TaskQueue**: 仅负责状态管理（入队、出队、状态查询、取消）
- **TaskExecutor**: 负责具体执行逻辑（渲染Prompt、调用LLM、写文件）
- 提供 `run_task_worker()` 函数用于后台任务处理

### 5. FileWatcher与EventBus分离
- **EventBus**: 独立的事件发布订阅系统，可被任何模块复用
  - `subscribe()` / `unsubscribe()` / `publish()`
  - 支持按事件类型过滤
  - 定义 `EventTypes` 常量
- **FileWatcher**: 仅负责文件系统监听
  - 监听文件变化并发布到 EventBus
  - 职责单一，易于测试

## 收益
- **Locality**: 修改实现不需要改调用方
- **杠杆**: 一套接口，多个实现（Mock/真实）
- **可测试性**: 核心逻辑可通过Mock独立测试
- **可扩展性**: EventBus可被新功能复用

## 术语
- **Module**: 任何有接口和实现的代码单元
- **Interface**: 调用者必须知道的所有信息
- **Depth**: 杠杆 - 少量接口承载大量行为
- **Seam**: 接口所在位置，可在此改变行为
- **Adapter**: 满足接口的具体实现
