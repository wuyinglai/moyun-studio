# 文件系统设计文档

## 一、总体目录结构

```

│
```

## 二、新增文件说明

### 2.1 文风指南 (style-guide.md)

**位置**：`projects/{project_name}/style-guide.md`

**用途**：定义小说的文风要求，指导 AI 生成符合期望的文字风格

**内容结构**：
```markdown
# 文风指南

## 一、文风定位
- 整体风格：简洁干练/华丽优美/口语化/古风典雅/冷峻硬朗/温暖治愈

## 二、示范文字
- 用户上传的示范文字片段

## 三、写作风格要点
- 句子节奏
- 描写密度
- 语言特点

## 四、写作禁忌
- 避免的表达方式

## 五、题材特点
- 题材特有的表达习惯

## 六、角色说话风格
- 主要角色的说话风格定义

## 七、参考范例
- 用户认可的优秀文风范例
```

**创建时机**：
- 创建项目时自动生成
- 用户可随时编辑

---

### 2.2 故事全局状态 (story-state.md)

**位置**：`projects/{project_name}/story-state.md`

**用途**：记录小说的全局状态，包括主角当前状态、势力变化、伏笔追踪等

**内容结构**：
```markdown
# 故事全局状态

## 一、故事基本信息
- 当前章节、进度、更新时间

## 二、主角状态
- 基础信息
- 能力/境界（根据题材调整）

## 三、主要资源/道具
- 资源列表及当前状态

## 四、势力关系
- 主角所属势力
- 相关势力

## 五、已揭示的重要设定
- 故事中已揭示的设定

## 六、伏笔追踪
- 已埋设但未回收的伏笔
- 已回收的伏笔

## 七、进行中的主线/支线
- 主线进度
- 支线状态

## 八、关键人物关系
- 人物关系最新状态

## 九、待处理事项
- 下一章节需要处理的事项

## 十、章节摘要（最近5章）
- 最近5章的摘要，用于提供近期上下文
```

**更新时机**：
- 每次生成新章节后自动更新
- 用户手动修改后更新

---

### 2.3 近期上下文 (recent-context.md)

**位置**：`projects/{project_name}/recent-context.md`

**用途**：存储最近N章的摘要，用于在生成章节时提供近期情节上下文

**内容结构**：
```markdown
# 近期上下文摘要

## 章节范围
- 起始章节、结束章节

## 摘要列表
- 最近5章的详细摘要

## 快速索引
- 人物状态速查
- 伏笔状态速查
- 势力关系速查
```

**更新时机**：
- 每次生成章节后自动追加/更新

---

## 七、Prompt 模板结构

每个 Prompt 模板目录下包含：

```
prompts/{category}/{type}/
├── meta.json              ← 模板元数据
├── main.md               ← 模板本体
└── blocks/              ← 可复用片段（按需创建）
    ├── xxx.md
    └── ...
```

**路径格式**：
- `prompts/generate/outline/`
- `prompts/extract/character/`
- `prompts/transform/polish/`

### main.md - 模板本体

```markdown
请根据以下信息撰写小说大纲：

类型：{{ genre }}
主题：{{ theme }}
主角：{{ protagonist }}

请生成包含以下部分的大纲：
1. 故事背景
2. 主要人物
3. 故事主线
4. 重要情节点

输出格式：
{% include 'blocks/output-format.md' %}
```

**支持 Jinja2 语法**：
- 变量：`{{ variable }}`
- 循环：`{% for item in items %}...{% endfor %}`
- 条件：`{% if condition %}...{% endif %}`
- **引用**：`{% include 'blocks/xxx.md' %}` - 引用本模板 blocks 目录下的片段

### meta.json - 模板元数据

```json
{
  "name": "大纲生成",
  "description": "根据基本信息生成小说大纲",
  "version": "1.0",
  "author": "作者名",
  "updated": "2026-05-08",
  "tags": ["outline", "generation"],

  "variables": {
    "genre": {
      "type": "select",
      "label": "小说类型",
      "options": ["玄幻", "科幻", "都市", "悬疑", "言情"],
      "default": "玄幻",
      "required": true
    },
    "theme": {
      "type": "text",
      "label": "核心主题",
      "placeholder": "例如：友情与成长",
      "required": true
    },
    "protagonist": {
      "type": "textarea",
      "label": "主角设定",
      "placeholder": "描述主角的基本信息...",
      "required": false
    },
    "word_count": {
      "type": "number",
      "label": "目标字数",
      "default": 5000,
      "min": 1000,
      "max": 50000
    }
  }
}
```

### 变量类型

| 类型 | 说明 | 示例 |
|------|------|------|
| `text` | 单行文本 | 用户名、标题 |
| `textarea` | 多行文本 | 详细描述 |
| `select` | 下拉选择 | 类型、风格 |
| `number` | 数字 | 字数、章节数 |
| `switch` | 开关 | 是否开启某功能 |
| `file` | 文件引用 | 关联已有文件 |

### blocks/ - 可复用片段

blocks/ 目录按需创建，用于存放可复用的片段。

```
prompts/generate/chapter/
├── meta.json
├── main.md
└── blocks/
    ├── opening-writing.md
    ├── climax-writing.md
    └── ending-writing.md
```

## 十、章节结构规则

### 10.1 层级关系

| 层级 | 命名格式 | 示例 | 说明 |
|------|----------|------|------|
| 卷 | `vol-{序号}` | `vol-01` | 由全文规模决定数量 |
| 章 | `ch-{序号}` | `ch-001` | **全局连续**，不随卷重置 |
| 节 | `sec-{序号}` | `sec-001` | **全局连续，每章固定4节** |

### 10.2 序号规则

- **全局连续**：章、节序号均不重置，从 001 开始递增
- **每章4节**：第2章的4节分别是 sec-005、sec-006、sec-007、sec-008

### 10.3 ch-meta.json - 章节元数据

```json
{
  "name": "第一章：意外觉醒",
  "start_section": 1,
  "status": "completed",
  "memory": {
    "summary": "主角张三在神秘遗迹中意外觉醒...",
    "key_points": ["觉醒时刻的力量波动", "与李四的初次相遇"],
    "foreshadowing": ["神器与主角身世有关"]
  },
  "story_state": "主角觉醒后，境界提升至练气期...",
  "pending_foreshadowing": [
    {"id": "fs-001", "content": "神器的真正来历", "buried_in": "ch-001"}
  ],
  "active_quests": [
    {"id": "q-001", "name": "寻找真相", "status": "进行中"}
  ]
}
```

| 字段 | 说明 |
|------|------|
| `name` | 章节名称 |
| `start_section` | 本章第一节序号 |
| `status` | 状态：draft/editing/completed/discarded |
| `memory` | 本章上下文记忆 |
| `story_state` | 本章时的故事状态（新增） |
| `pending_foreshadowing` | 待回收伏笔（新增） |
| `active_quests` | 进行中支线（新增） |

**说明**：
- `vol_id`、`chapter_id` 从目录结构推断（如 `vol-01/ch-001/`）
- 统计类字段（字数、节列表）按需从目录动态计算
- memory 是否过期通过比较章节文件修改时间判断

### 10.4 章节 Memory 机制

每章拥有独立的 `memory`，用于：

| 用途 | 说明 |
|------|------|
| 支持重新生成 | 重新生成某一节时，基于该章 memory 生成 |
| 上下文拼接 | 写新章节时，读取前 3 章的 memory 拼接上下文 |

**更新时机**：
- 章节写完后自动生成/更新 memory
- 用户手动修改章节后更新 memory

### 10.5 vol-meta.json - 卷元数据

```json
{
  "name": "第一卷：少年出山"
}
```

**说明**：
- `vol_id` 从目录名推断（如 `vol-01/`）

## 十三、版本管理

### 13.1 Prompt 快照

- 保存位置：`prompts/_backup/`
- 触发时机：每次保存 Prompt 模板时自动生成
- 命名格式：`{category}_{type_slug}_v{n}_{date}.md`
- type_slug：type 的 slug 化版本（中文转拼音或拼音首字母）

**示例**：
- `generate_outline_v1_20260508.md`
- `extract_character_v2_20260510.md`
- `extract_zdyfx_v1_20260511.md`（用户自定义 → zdyfx）

### 13.2 项目快照

- 保存位置：`projects/{project_name}/backup/`
- 触发时机：手动触发或定时触发
- 命名格式：`v{n}_{date}.md`

### 13.3 Git（可选）

- 在 `workspace/` 根目录初始化 Git 仓库
- 开启后自动追踪所有文件变更

**文件不支持物理删除**

| 提取结果废弃 | 提供文件名（如 `plot_001`），标记为 inactive |
| 快照 | 可清理旧快照，但保留最近 N 个 |
| 误创建 | 记录错误，下次避免 |

## 十九、异常处理

### 19.1 文件丢失

| 情况 | 处理方式 |
|------|----------|
| 章节文件丢失 | 提示用户，检查 ch-meta.json memory 是否需要更新 |
| 角色档案丢失 | 提示用户，检查 characters/ 目录 |
| 提取结果丢失 | 提示用户，检查 materials/extracted/ 目录 |
| style-guide.md 丢失 | 使用默认文风定义 |
| story-state.md 丢失 | 重新初始化 |
| meta.json 丢失 | 阻止项目加载，提示用户重建 |

### 19.2 目录结构破坏

| 情况 | 处理方式 |
|------|----------|
| 章节目录下无 ch-meta.json | 阻止操作，提示用户修复 |
| 卷目录下无 vol-meta.json | 阻止操作，提示用户修复 |
| 目录/文件命名不符合规范 | 阻止操作，提示用户重命名 |

### 19.3 数据验证

| 检查项 | 验证规则 |
|------|----------|
| 章节序号连续性 | 同一卷内章节序号连续 |
| 节序号连续性 | 每章固定4节，序号全局连续 |
| ID 唯一性 | 同类型下 ID 不可重复 |
| 路径有效性 | 引用路径必须存在 |

## 二十、规则总结

1. **目录即分类**：Prompt 模板按 `generate/extract/transform` 分类，extract 下子目录由用户自由创建
2. **模板结构**：每个模板包含 `main.md`（内容）+ `meta.json`（元数据）+ `blocks/`（按需创建）
3. **模板引用**：使用 Jinja2 `{% include 'blocks/xxx.md' %}` 语法引用本模板的片段
4. **章节结构**：卷 > 章 > 节，章和节序号全局连续，每章固定4节
5. **单文件存储**：角色档案和提取结果都是每个对象单独一个文件
6. **角色档案**：`characters/` 目录统一存储角色档案
7. **提取结果存储**：`materials/extracted/{type}/` 存储提取结果，每个结果单独一个文件
8. **版本管理**：Prompt 和项目都有独立的快照机制
9. **信息推断**：ID 类信息从目录/文件名推断，不重复存储
10. **文件生命周期**：每类文件有明确的创建、更新、删除规则
11. **约束限制**：目录/文件名有严格的命名规范
12. **异常处理**：文件丢失、目录结构破坏等情况的处理方式已定义
13. **新增质量保障**：新增 style-guide.md、story-state.md、recent-context.md、feedback/、revision-log/ 等文件，提升生成质量
14. **Prompt 增强**：章节撰写和续写模板新增多个引用变量，增强上下文感知能力
