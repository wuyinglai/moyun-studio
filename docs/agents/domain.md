# Domain Docs

工程技能在探索代码库时应如何消费本项目的领域文档。

## 探索前阅读

- 根目录的 `CONTEXT.md`（项目领域术语和上下文）
- `docs/adr/` - 阅读与当前工作领域相关的架构决策记录（ADR）
- 如需创建新的架构决策记录，使用 `000X-描述性标题.md` 格式命名

如上述文件不存在，静默继续。不要主动标记其缺失。

## 目录结构

单上下文仓库（大部分仓库）：

```
/
├── CONTEXT.md              # 领域术语和上下文
├── docs/
│   ├── adr/               # 架构决策记录
│   │   ├── 0001-决策标题.md
│   │   └── 0002-决策标题.md
│   └── agents/            # Agent 配置文件
├── backend/               # 后端代码
└── workspace/             # 用户工作区
```

## 使用词汇表中的术语

当输出需要命名领域概念时（在 issue 标题、重构提案、假设、测试名称中），使用 `CONTEXT.md` 中定义的术语。不要使用词汇表明确避免的同义词。

如果所需概念尚不在词汇表中，这是一个信号——要么是你在发明项目未使用的语言（重新考虑），要么存在真正的缺口（记录下来供 `/grill-with-docs` 处理）。

## 标记 ADR 冲突

如果输出与现有 ADR 矛盾，明确提出而非静默覆盖：

> _与 ADR-0007（事件溯源订单）矛盾——但值得重新讨论，因为……_
