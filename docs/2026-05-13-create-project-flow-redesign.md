# 新建项目流程改造设计

## 概述

将新建项目的多步骤弹窗流程改为「弹窗输入参数 → 直接创建项目 + 流式写入编辑器文件」的单步流程，与正文生成行为保持一致。

## 现状

当前 CreateProjectModal 有 5 个步骤（1 → 1.5 → 2 → 2.5 → 3），生成结果展示在弹窗内，用户需多次确认才能完成创建。这导致：

- 弹窗交互路径长，用户需要等待弹窗内完成生成才能操作
- 大纲生成在弹窗内等待，没有流式效果
- 创建成功后还要再点「开始写作」才进入编辑器

## 目标流程

```
轻量弹窗（选参数） → 点「生成并打开」
  → 弹窗关闭
  → 后端创建项目 + 文件结构
  → 前端跳转 /project/{id}
  → 自动打开 书名与创意.md
  → SSE 流式写入内容到文件（用户实时可见）
```

后续生成（大纲、正文）统一走工具栏「生成下一个文件」按钮，行为一致。

## 改动范围

### 1. CreateProjectModal.vue

- 移除多步骤逻辑（step 1.5, 2, 2.5, 3）
- 改为单页：展示创作参数表单（题材、基调、写作风格、背景、主题、作品规模、作者）
- 「生成并打开」按钮：点击后关闭弹窗，调用后端创建项目，然后跳转编辑器
- 删除 `useProjectWizard` 依赖中的步骤管理代码

### 2. useProjectWizard.ts

- 移除步骤管理：`currentStep`, `bookIdea`, `outline`, `editedOutline` 等中间状态
- 简化接口：只保留 `generateBookIdea()` → 返回结果并直接创建项目
- 或者直接在 CreateProjectModal 中内联逻辑，不再通过 wizard 管理

### 3. 项目创建后跳转

- 创建项目成功后，`router.push(`/project/${projectId}`)`
- 路由 `beforeEnter` 会加载文件树和项目数据
- 需要确保新项目在跳转前已写入 `projectStore`

### 4. 流式写入文件

方案：**后端主动推送**，不依赖前端额外请求。

- 后端在创建项目 + `书名与创意.md` 后，立即开始 AI 生成，通过 SSE 推送：
  - `file-created` → 前端刷新文件树
  - `generation` → 前端 `editorStore.appendContent` 写入编辑器（已有实现）
  - `done` → 生成结束
- 前端只需在跳转后打开 `书名与创意.md`（通过路由参数或 `fileStore.openFile`），SSE 事件会自动更新编辑器内容
- 与现有正文生成一致：工具栏「生成下一个文件」已通过 `/api/generate` + `parseSSEStream` 实现流式写入

### 5. 右侧面板显示 Prompt

- 利用现有右侧面板（RightPanel），在生成状态下展示当前 prompt
- 用户可查看但不可编辑（仍走原有布局）
- 生成结束后 prompt 信息保留，供参考

## 不涉及改动的部分

- 三栏布局（AppLayout）不变
- 工具栏按钮（重写、生成下一个文件）行为不变
- 聊天面板不变
- 右侧面板整体结构不变
- 路由结构不变

## 实现顺序

1. 改造 `CreateProjectModal.vue` + `useProjectWizard.ts`（精简为单步）
2. 实现「点击生成 → 创建项目 → 跳转编辑器」流程
3. 实现进入编辑器后自动流式写入 `书名与创意.md`
4. 右侧面板展示 prompt 信息
