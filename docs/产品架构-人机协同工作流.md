# 墨韵产品架构：人机协同工作流

本文用于统一后续改造的产品语言。墨韵不再只被理解为“Prompt 管线编辑器”，而是一个面向长篇小说的 **人机协同创作系统**：AI 负责生成、总结、审稿和候选改写；作者负责表达意图、选择方向、确认关键状态；工作流负责把这些动作稳定串起来。

## 一、三层结构

```text
Workflow 工作流
  Chain 执行组
    Node 执行节点
```

### 1. Workflow 工作流

工作流负责安排完整任务，例如：

- 创建一部小说
- 生成并修订一节正文
- 更新故事引擎和近期上下文
- 批量整理角色、伏笔、阶段规划

工作流关心“步骤顺序、暂停恢复、变量传递、错误处理、执行记录”，不直接关心某个 Prompt 的具体写法。

### 2. Chain 执行组

执行组是一组紧密相关的节点，通常完成一个中等粒度目标，例如：

- 生成正文候选稿
- 质量审稿与补强
- 提取章节记忆
- 对话改稿

执行组可以被专业版显式编辑，也可以被爽文模式隐藏调用。

### 3. Node 执行节点

节点是最小可执行单元。Prompt 节点只是其中一种。

| 节点类型 | 执行者 | 用途 |
| --- | --- | --- |
| Prompt Node | AI | 生成、总结、改写、审稿、提取 |
| Human Node | 用户 | 确认、修改、选择、评分、补充意图 |
| File Node | 系统 | 读取、写入、复制、删除、生成候选文件 |
| Memory Node | AI + 系统 | 更新故事引擎、近期上下文、角色状态 |
| Quality Node | AI + 系统 | 审稿、打分、判断是否补强 |
| Condition Node | 系统 | 根据变量、评分、用户选择决定分支 |
| Retrieval Node | 系统 | 检索前文、角色、伏笔、设定 |
| Patch Node | AI + 系统 | 对已有文件生成可审阅修改 |
| Version Node | 系统 | 快照、候选稿、采用、回滚 |

## 二、人的互动不是备注

人的互动有两种入口：

### 1. 对话入口

作者随时用自然语言表达意图，例如：

- “这一节不要让女主太快相信男主。”
- “把前三章的节奏压快一点。”
- “主角不能像工具人，要更张扬。”

系统应把这些内容解析成“作者意图”，进入候选改稿、下一场景生成或记忆校正流程。对话适合表达灵感、偏好和局部修改请求。

### 2. Human Node 入口

当工作流走到必须由作者把关的位置时，进入人工节点，例如：

- 选择剧情方向
- 确认角色设定
- 审核记忆写入
- 编辑正文候选稿后采用

人工节点的状态应明确为 `WAITING_FOR_USER` 或等价状态。用户处理后，工作流继续执行。

## 三、候选稿是统一安全机制

所有会改正文、设定、记忆的操作，默认先进入候选稿或候选补丁：

```text
原文件保持不变
AI 生成候选内容
用户预览候选
用户采用后才替换或写入正式文件
采用后更新故事引擎、近期上下文和质量摘要
```

这套机制适用于：

- 重写当前场景
- 更爽一点
- 更合理一点
- 对话改稿
- 专业版 Prompt 改写
- 记忆更新确认

爽文模式可以只展示“采用/放弃”，专业版应展示候选来源、变量、节点日志和影响文件。

## 四、故事状态的权威来源

长篇连续性不靠大纲兜底，而靠以下状态持续更新：

- 人物欲望
- 冲突推进
- 场景直觉
- 前文记忆
- 读者期待
- 阶段性目标
- 角色状态
- 伏笔与未回收问题

生成候选稿时可以读取这些状态，但不应立刻写入。只有正式正文被保存或候选稿被采用后，才触发 Memory Node 更新。

## 五、专业版与爽文模式的关系

| 能力 | 爽文模式 | 专业版 |
| --- | --- | --- |
| 章节生成 | 用户选爽点卡，系统自动写 | 用户可编辑工作流和 Prompt |
| 作者意图 | 对话和简单参数 | 对话、变量、人工节点、工作流输入 |
| 候选稿 | 采用/放弃 | 候选文件、差异、节点日志 |
| 故事状态 | 摘要展示 | 可查看、可审阅、可手动修正 |
| 文件操作 | 隐藏 | File Node 显式可配置 |
| 质量控制 | 自动审稿摘要 | Quality Node 可配置阈值和分支 |

两种模式应共用项目文件、故事状态、候选稿和工作流能力，只是暴露复杂度不同。

## 六、用户使用故事

### 爽文用户

用户打开爽文模式，选择一张爽点卡。编辑器立刻显示工作状态并开始流式出字。生成完成后，系统在后台审稿、更新故事引擎，并提示一句质量摘要。用户不满意时点“更爽一点”，系统生成候选稿。用户预览满意后点“采用候选稿”，正式正文才被替换。

### 专业作者

作者在专业版打开“生成第 8 章”工作流。系统先读取近期上下文和角色状态，再生成章节方向。工作流暂停在人工选择节点，作者选择一个方向并补充要求。随后 AI 生成正文候选稿，作者编辑后确认。系统写入正式正文，并在记忆更新节点等待作者审核关键状态，避免错误记忆污染后续长篇。

### 自定义工作流用户

用户创建一个工作流：读取前三个场景正文，检索角色卡，生成下一场景候选稿，质量审稿，低分则自动补强，高分则进入人工确认，确认后写入文件并更新故事引擎。用户不需要写后端代码，只需要组合节点。
